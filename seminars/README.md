ни заданий, ни ловушек, ни бюджета и пропустит ноутбук как непроверяемый.

## Накопительная система

Правило 10.4 стандарта: индекс, эмбеддинги и дообученные веса пишутся в фиксированную папку на
Drive и **переиспользуются дальше** — к концу курса у студента одна собранная поисковая система,
а не семь разрозненных ноутбуков.

**Но каждый семинар обязан запускаться в одиночку.** Нет артефакта прошлого занятия — ноутбук
строит его сам в уменьшенном масштабе и говорит об этом вслух. Пропустивший занятие не выпадает
из курса.

### Прогон целиком

Гейт читает разметку, а не выполняет код. Перед сдачей ноутбук прогоняется **полностью**,
с подстановкой опубликованных решений вместо заглушек — иначе решения в `<details>` никем
не проверены. Авторское окружение (не студенческое, оно в Colab):

```bash
/opt/anaconda3/bin/python3.12 -m venv _research/.venv-seminars   # один раз
_research/.venv-seminars/bin/pip install "numpy<2" scikit-learn matplotlib
```

### Порядок прогона

Тетрадки связаны артефактами: каждая кладёт результат в `ARTIFACTS` (по умолчанию
`./artifacts` рядом с ноутбуком), следующая его подхватывает. Порядок совпадает с порядком
курса — гнать надо в нём:

| # | тетрадка | берёт из прошлой | оставляет после себя |
|---|---|---|---|
| 1 | `lab-bm25` | — | `bm25_index.json` |
| 2 | `hw-ranking-metrics` | `bm25_index.json` | `metrics.py` |
| 3 | `lab-cascade` | `metrics.py` | `cascade.json`, `corpus_emb.npy` |
| 4 | `hw-alliance` | `cascade.json` | `fusion.json` |
| 5 | `lab-ann` | `corpus_emb.npy` | `ann.json` |
| 6 | `hw-rag` | — | `rag.json` |
| 7 | `project-search` | всё перечисленное | `defence.json` |

С 3-й нужен GPU: `lab-cascade`, `hw-alliance`, `lab-ann`, `hw-rag`, `project-search` грузят
`all-MiniLM-L6-v2` и `ms-marco-MiniLM-L-6-v2`. Первые две — чистый CPU.

**Артефакты цепочки лежат на Drive** — `/content/drive/MyDrive/dls-2026/artifacts` (правило
10.4; первая ячейка монтирует Drive сама). Поэтому обрыв рантайма цепочку НЕ рвёт: следующая
тетрадка находит индекс и эмбеддинги на месте, даже если между занятиями прошла неделя.
Без Drive (локальный запуск, отказ в доступе) ноутбук говорит об этом вслух и пишет рядом с
собой — занятие отработает целиком, но следующее не подхватит артефакт и соберёт уменьшенный
свой: `hw-alliance` без `cascade.json` возьмёт 400 документов вместо 1500 и 40 запросов вместо
80. Для контрольного прогона нужны полные числа, так что Drive лучше не отключать.

В сам архив прогона артефакты цепочки НЕ попадают — там только `<имя>.json` и `run_log.txt`,
вместе около 5 КБ. Класть туда индекс (1,2 МБ) и эмбеддинги (~2,3 МБ) незачем: обратно в Colab
их всё равно не залить, `files.upload()` запрещён §10.1.

И не задавай `SMOKE=1`: это режим быстрой проверки на срезе (200 документов вместо 2000).

### Прогон на T4: что делает человек, а что делается само

Человек делает три вещи — готовит копии, прогоняет, жмёт ссылку. Всё остальное делают скрипты.

```bash
python3 scripts/sync_solved.py        # seminars/*.ipynb → tmp/colab-t4/*.ipynb с решениями
```

Дальше прогон в Colab по порядку из таблицы выше. **Последняя ячейка каждого занятия**
складывает в каталог прогона две вещи — `<имя>.json` (все числовые результаты + конфигурация
рантайма) и `run_log.txt` (журнал печатей всего занятия), — жмёт их в zip и показывает
кнопку-ссылку «⭳ Скачать прогон». Жмёшь — архив падает в загрузки браузера.

Когда все семь скачаны:

```bash
python3 scripts/import_runs.py --gate   # разложить архивы из ~/Downloads и прогнать G29
```

Дампы лягут в `seminars/runs/` (CPU) или `seminars/runs-t4/` (ускоритель) — маршрут выбирает
сам дамп по `runtime.gpu`, поэтому T4-прогон не может затереть базовый CPU-дамп, с которым его
же и сравнивает шаг [T4] гейта. Журналы всегда ложатся в `seminars/runs/logs/<имя>.log`.

npm тут только обёртка: `npm run runs:prepare` = `sync_solved.py`, `npm run runs` =
`import_runs.py --gate`.

**Почему архивом, а не файлом.** Каталог прогона живёт на машине Colab и умирает вместе с ней;
до репозитория доезжает только вывод ячейки — и ссылка внутри него. Журнал в архиве нужен не
меньше чисел: по нему видно, что именно печатало занятие, без возврата самой тетрадки.

### Что каждый семинар обнаружил на прогоне

Правило порядка работы (§15a стандарта) — сначала код, потом прогон, разборы по реальным
числам — родилось не на пустом месте. Вот что прогон опроверг в уже написанном тексте:

* **`lab-bm25`** — разбор утверждал «сырой счёт совпал с доской», а там ничья 3:3, и порядок
  решал тай-брейк по имени. Плюс `assert` сравнивал списки там, где совпасть могли только
  множества.
* **`hw-ranking-metrics`** — BM25 оказался **хуже** среднего случайного перемешивания
  (0,677 против 0,771): прокси-разметка и лексический ранжировщик меряют разное. И «нагнутый»
  порядок из данных лекции не выигрывал ни по одной метрике — задание переписано.
* **`lab-cascade`** — первый прототип пришлось выбросить целиком: с релевантностью
  по категории задача вырождалась.
* **`hw-alliance`** — первый за курс различимый результат, и тут же разбор, что синергии в нём
  нет: RRF унаследовал полноту би-энкодера.
* **`lab-ann`** — три утверждения опровергнуты сразу, включая знак расхождения между согласием
  и потерей конечной метрики.
* **`hw-rag`** — базовая линия «без чанкования» оказалась методологически слабой: энкодер
  видит первые ~190 слов при медиане документа 268.
* **`project-search`** — узкое место оказалось не там, где напрашивалось, а рекомендуемое
  действие было вписано заранее и не следовало из диагноза.

Зелёный G24 значит «нет регрессии по механически проверяемой половине», а **не** «хорошо».
Половина стандарта — §4 (четыре хода разбора), §5.1 (учим тихим ловушкам), §16 (дисциплина
сомнения в собственном числе) — машинно не проверяется и остаётся на ревью. Последний пункт
чек-листа §14 никакой гейт не заменит: **ты прошёл семинар целиком сам, от чистого ядра до
последней ячейки.**
