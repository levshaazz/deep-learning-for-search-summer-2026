Labs Lab 3

The index at scale: build ANN by hand (IVF · PQ · IVF-PQ)

Take your Lab-2 dense embeddings and index them the way billion-scale systems do — build IVF, Product Quantization and IVF-PQ by hand, and measure the recall / work / memory triangle against exact search.

Goal

You already retrieve with exact cosine search (Lab 2) — that is O(N·d) per query, fine for a few thousand documents and hopeless for millions. Build the two orthogonal families of approximate nearest-neighbour index by hand — a partitioning index (IVF) and a compression index (Product Quantization) — compose them (IVF-PQ), and show with your own numbers exactly what each buys and what it costs against an exact baseline. "HNSW vs PQ" is a category error: partition-or-graph and how-many-bytes-per-vector are two different axes that compose.

Dataset & setup

This Lab (and Homework 3) use EnterpriseRAG-Bench. The questions config is tiny (500 rows); the documents config is ~500K long docs (several GB) — do NOT materialize it all, STREAM it and keep only what you need. Build a ~5K-doc laptop corpus = one source_type filtered from the stream (cap/sample to 5K with the course seed 20260605 if larger) UNION every expected_doc_id of your fixed question subset (the first 30 by question_id), so the gold documents are guaranteed indexed. Embed title+content and each question with your Lab-2 SBERT (all-MiniLM-L6-v2) — it truncates a long doc to its 256-token window, which is fine here because ANN recall is measured against the SAME embeddings — and L2-normalize to unit vectors (so cosine == dot). FIX random_state=20260605 for every k-means / codebook fit and any sampling, or your tradeoff table will not reproduce. Relevance for the retrieval sanity-check is expected_doc_ids; but the ANN recall below is measured against your OWN exact top-10, not qrels — you are measuring index fidelity, not retrieval quality.

Tasks

  1. Exact baseline (the recall ground truth): flat cosine search over the unit vectors; record the exact top-10 per query. Every ANN recall@10 below is measured against THIS list: recall@10 = |ANN top-10 ∩ exact top-10| / 10.
  2. IVF by hand: run k-means (nlist ≈ √N centroids; sklearn KMeans is an allowed helper) to induce Voronoi cells; file each document into its nearest centroid’s inverted list. Query = rank the query against the nlist centroids, then exact-scan ONLY the top-nprobe lists. Sweep nprobe ∈ {1, 2, 4, 8, 16, nlist}; plot recall@10 and the fraction of the corpus scanned against nprobe, and mark the knee where recall saturates. Exhibit one query where nprobe=1 drops a true neighbour sitting just across a cell boundary.
  3. Product Quantization by hand: split each d-dim vector into m contiguous subvectors; train one codebook of k centroids per subspace (Lloyd’s k-means — track the falling inertia). Store each document as m codes of ⌈log₂k⌉ bits each (one byte per code at k=256). At query time build the m×k asymmetric-distance (ADC) table once, then score every document as m table lookups + (m−1) adds — no decompression. Report the PACKED bytes/vector = m·log₂(k)/8 (the on-disk cost, not the size of a uint8 numpy array) and the compression ratio dim·4/bytes. Then EXACT-re-rank the PQ top-100 with full vectors and report recall@10 with and without the re-rank: PQ alone has a hard recall ceiling well below 1.0 — the exact figure is corpus- and (m,k)-dependent, expect roughly 0.4–0.8 here, do NOT treat a specific number as the target — because its loss is baked into the stored codes; the exact re-rank is what recovers it (the same "cheap retrieve, exact re-rank" division of labour as the cross-encoder cascade).
  4. (m, k) memory sweep: vary m ∈ {4, 8, 16} (all divide the 384-dim MiniLM vector) and k ∈ {16, 256}; plot recall@10 (after the exact re-rank) against the PACKED bytes/vector. Read off the memory-vs-recall tradeoff and confirm the bytes formula m·log₂(k)/8 against your packed sizes — note k=16 is 4 bits/code (half a byte), so it only matches if you count packed bits, not a uint8 array.
  5. IVF-PQ (compose them): IVF decides which vectors (skip cells), PQ+ADC scores each survivor cheaply, then exact-re-rank the shortlist. Report one combined row: recall@10, fraction scanned, bytes/vector.
  6. The tradeoff table + analysis: one table, rows {exact, IVF@knee, PQ+re-rank, IVF-PQ} × columns {recall@10, fraction of corpus scanned, bytes/vector, compression×}. Write a half-page analysis of the recall-vs-work-vs-memory triangle: why PQ never ships without an exact re-rank, why IVF’s speed comes from skipping (not shrinking), and the boundary-neighbour failure — each claim pinned to a concrete number from your run.
  7. Optional (HNSW trace): CONSTRUCT a small graph + query where greedy descent from a far entry point gets trapped, trace the descent, and sweep efSearch — exhibit ef=1 stuck in a local minimum (low/zero recall) while ef ≥ 2 escapes to full recall. One sentence: why does a wider frontier escape the trap? (The trap only shows on a graph built to have one; a random small graph may not.)

Deliverables

lab.py (or a notebook) that runs end-to-end and prints the tradeoff table, plus a 1-page report: the tradeoff table, the nprobe recall/work curves, the (m,k) memory-vs-recall plot, and the analysis paragraph.

Stepik autograder — control numbers

On Stepik the index LOGIC is checked by a deterministic autograder (stepik/graders/grader_lab3_ann.py): 400 synthetic unit vectors (d=16, 8 clusters, seed 20260605); the coarse centroids and the PQ codebooks are GIVEN as fixtures — you implement the index, not the k-means. All distances are squared L2, ascending. Tolerance 1e-4; the EnterpriseRAG-Bench run goes into the report (peer-reviewed).
