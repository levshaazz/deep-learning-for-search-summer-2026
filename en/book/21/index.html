A good neighbour is not yet an answer

Séréga has a shortlist and Sir Cosine has put it in order. The next question is harder: may the Ship answer from it? A document can mention every word in a query and still omit the one condition that decides the answer. Ranking chooses which document to inspect first; a decision policy chooses what the system is allowed to do. Neither job disappears when the score becomes neural.

This supplementary chapter belongs after L16, at the return from Generate to Measure in Get Data → Measure → Rank → Generate. Jev is our concrete case study, not a promised replacement for every reranker. We will turn a typed distribution into an ordering, test its probability scale, and price an action. All device examples and numeric fixtures below are synthetic teaching data, not measured Jev responses or claims about real hardware.

Order, probability, action

Ask: can monitor M2 connect to port U1 on Vega14 using cable C7? Passage A advertises the Vega family and accessories. B says C7 carries fictional profile V7 and works with M2, but says nothing about Vega14. C explicitly confirms this exact connection. D discusses servicing the keyboard of another laptop. Their hand-written usefulness grades are A=1, B=2, C=3, D=0. The deliberately bad starting order A,D,B,C is an illustration, not a BM25 measurement.

Now change C to say that the connection is not supported. It still answers the question completely. Useful relevance, answerability, and support for a positive claim are different targets. Three reports must therefore remain separate: ranking metrics assess the order; probability metrics assess a specified event; policy loss assesses the consequences of the chosen action. A win in one report does not certify the other two.

An interface, not an invented architecture

Jev takes a shared state and typed questions. Think of the observable contract as \(f_\theta(\text{state},\text{question})\to p\). The state contains query and passage; instructions define the judgment; criteria define the possible answers. Our code subsequently maps the returned distribution to a ranking or an action. This diagram describes an API boundary, not the model’s hidden layers. TypeSafe introduction.

The placement in the search cascade is ordinary: a bi-encoder or lexical search finds candidates; an expensive pair evaluator examines the shortlist. Jev plays the latter role in this experiment. It does not build an index or generate the final answer. A typed result removes an output-format ambiguity, not semantic error: a perfectly valid category can still be wrong. Generative models can also use constrained formats, so compare decisions and costs, not the presence of JSON.

Three types, three meanings

Choice selects among named alternatives and returns their probabilities. For a claim, use supports / contradicts / not_stated: the last option prevents a forced verdict when evidence is missing. Score uses ordered descriptive levels and returns their distribution plus the probability-weighted mean of level indices. A fractional score is a position on that rubric, not a probability. Noul estimates “yes” for one binary question. Primitives.

Use all three on C: usefulness level, relation to the positive claim, and whether the fragment alone is sufficient. They answer different questions even when their outputs agree. A Noul near one half expresses uncertainty about its event, not half a document’s relevance. Avoid numerical extraction by Score: a semantic rating of “many items” is not an exact count. Count or compare structured values in ordinary code.

Make the boundary observable

Our rubric has four levels: 0, no useful information for the exact question; 1, same topic without answer-bearing facts; 2, some necessary facts but an incomplete answer; 3, enough explicit information to answer, positively or negatively. The intended adjudication rule is the highest fully satisfied level. Give each level a complete description: “better than the previous level” is not a self-contained criterion. Test borderline examples with humans before asking a model.

B is the important boundary case. It establishes cable-to-monitor compatibility but not laptop-port support. Calling B “highly relevant” hides the missing condition; grade 2 explains it. If annotators disagree because one silently imports hardware knowledge, the target is not yet stable. Require evidence from the supplied text and record unresolved ambiguity. Changing a rubric after viewing the test scores changes the task, not merely the wording.

Parallel does not mean independent events

Questions in one request share the state but do not consume each other’s answers. If the second judgment needs the first output, make a second request with an explicit new state. A question identifier is a key for your code, not a substitute for instructions: write what “passage”, “query”, and “claim” mean. Question contract.

Execution structure says nothing about statistical independence. The events “contains a useful fact” and “supports this claim” may depend on the same sentence. Multiplying their marginal probabilities does not generally produce the probability of a correct answer. Likewise, ask one binary event and compute its complement as one minus p; separately phrased questions can disagree. If a joint event is the actual decision target, define and validate that joint event instead of inventing its probability from convenient fields.

What RLCD does and does not tell us

TypeSafe calls its approach Reinforcement Learning for Calibrated Decisions, or RLCD. The public description stresses decisions with usable probability estimates. It does not supply a complete reproducible training recipe, the exact RLCD objective, or a full computational graph. We therefore cannot derive the implementation from the acronym or assert a parameter count. Machine-learning primer.

Separate three levels of knowledge: an observed API contract, a vendor statement about training, and evidence from an independent held-out experiment. They support different claims. An intention to train calibrated predictions does not establish calibration on Russian support queries. The next derivation motivates honest probability reporting in general. It is deliberately not labelled as Jev’s secret loss function.

Why a proper score rewards honesty

Let an event occur with true probability \(\pi\), and let the reported probability be \(p\). With binary outcome \(Y\), the expected squared error is \(\mathbb E[(p-Y)^2]=\pi(p-1)^2+(1-\pi)p^2=(p-\pi)^2+\pi(1-\pi)\). The second term does not depend on the report. The first is nonnegative and vanishes exactly when \(p=\pi\). That is the mechanism behind the Brier score being a strictly proper scoring rule for this binary event.

The calculation separates avoidable error from uncertainty that remains even for an honest forecast. It does not reveal the true probability of a single document, nor prove that a learned model reaches the minimum. Labels, population, and model capacity still matter. Most importantly, this is a general mathematical argument—not a published derivation of RLCD.

Choose a utility before sorting

A distribution is not yet a ranking rule. Choose the value of each grade: here \(g(r)=2^r-1\), giving gains 0,1,3,7. Then compute \(s(q,d)=\sum_r P(r\mid q,d)g(r)\). This is expected gain. Our choice rewards a complete answer much more than a topical mention; a different application may choose a linear gain. The policy is visible in code instead of hiding inside the word “relevant”.

Why sort by this expectation? In DCG, swapping two documents changes the expected total by \((\mathbb E[g_a]-\mathbb E[g_b])(w_i-w_j)\), where the earlier position has larger discount weight. Put the larger expected gain first and the difference is nonnegative. Linearity of expectation needs no independence between document labels. The argument assumes fixed candidates and additive position-discounted utility; it does not prove optimal diversity or expected nDCG with a random denominator.

C earns its place by arithmetic

Use the synthetic distribution for C over grades 0–3: [0.02,0.03,0.15,0.80]. The expected grade is \(0.03+2\times0.15+3\times0.80=2.73\). The expected gain is \(0.03+3\times0.15+7\times0.80=6.08\). They average the same probabilities against different values. Score.score represents the first calculation, not the second. Score semantics.

The same synthetic calculation gives A: expected grade 1.15, gain 1.50; B: 1.95 and 3.25; D: 0.21 and 0.29. Descending expected gain therefore produces C,B,A,D. Check each distribution sums to one before calculating.

Do not exponentiate the mean grade: \(\mathbb E[2^r-1]\ne 2^{\mathbb E[r]}-1\) in general. The nonlinear function acts on outcomes before averaging. Keep the full distribution in the cache so that another utility can be evaluated without a second model call.

A changed utility can reverse the order

The A–D example happens to keep its order under both linear and exponential gain. Do not promise movement whenever a slider moves. To expose the mechanism, use a separate synthetic pair: X=[0,0.45,0.55,0] and Z=[0.55,0,0,0.45]. Linear expected grades are 1.55 and 1.35, so X wins. Exponential expected gains are 2.10 and 3.15, so Z wins. Z offers more chance of a complete answer and more chance of nothing useful.

Neither sorting rule is universally right. The choice expresses how valuable a complete answer is relative to partial information. Record that choice before evaluating outcomes. In the next interactive, first inspect A–D, then switch to X/Z, then change utility. The model distribution does not change; only our decision rule does. That is the point of keeping the two visible.

A distribution describes several possible grades. The four masses sum to one; none is a free-text confidence statement.

Multiply each probability by the utility of that grade, then sum. For document C, exponential expected gain is 6.08.

Sort by expected utility. Change to X/Z and compare linear and exponential gain; the policy chooses different orders from the same distributions.

Return to L5 and keep the labels fixed

Evaluate the synthetic ranking with the hand-written grades, not with the predictions used to sort it. In the starting top three A,D,B, the gains are 1,0,3. Thus \(DCG@3=1+0/\log_2 3+3/2=2.5\). The ideal top three C,B,A give \(IDCG@3=7+3/\log_2 3+1/2\approx9.3928\). The starting nDCG is about 0.2662; sorting to C,B,A,D makes it one for this toy candidate set.

Define binary usefulness as grade at least two. B and C are useful. The first useful document moves from rank three to rank one, so reciprocal rank moves from one third to one; Recall@3 moves from one half to one. This is RR for one query, not MRR over a dataset. The exercise proves the arithmetic of a constructed example. It supplies no evidence that real Jev scores recover these labels.

The missing document cannot be reranked

Remove C before the second stage. The best available order is now B,A,D, but the complete answer has vanished. A candidate-conditioned nDCG can still reach one because its ideal list contains only available candidates. That is not a contradiction: the metric answers “how well did we sort this set?”, not “did search find everything needed?”. Report the first-stage recall separately, using a broader judged pool when the full corpus is not labelled.

A denominator is part of a metric’s definition. Label candidate-conditioned nDCG and corpus-pool nDCG as separate columns. Do not silently treat unjudged documents as irrelevant. If all gains in the relevant ideal pool are zero, nDCG is undefined under this chapter’s convention; exclude it from the mean and report how many queries were excluded. Keep no-answer queries in the controller evaluation instead of making them disappear.

Confidence describes a distribution, not truth

Jev’s confidence is derived from the shape of the returned distribution. The documentation does not give its exact formula, so do not silently substitute normalized entropy. Noul has no separate confidence field. Confidence. A concentrated but wrong distribution is still concentrated: the statistic is not an independent witness that the answer is correct.

Keep three quantities apart: the expected rubric level, the probability of a named event, and a summary of distribution shape. If you compute entropy yourself, label it as your diagnostic. To use any confidence threshold operationally, measure its association with the relevant errors on held-out data. An impressive value on one example cannot establish that relationship; the outcome label must come from outside the model.

Name the event before reading the number

For passage usefulness define \(Y=\mathbf 1[r\ge2]\). From a distribution over mutually exclusive grades, the probability of that event is \(p_\text{useful}=P(r=2)+P(r=3)\). This is a sum over outcomes, not a new model inference. It is not the same event as “this passage answers the whole question”: grade two explicitly allows missing facts.

Later the controller will use \(Y_\text{ctx}\), sufficiency of the complete selected context. These events require different labels and may require different probability calibration. Even a correctly sufficient context does not guarantee that a generator writes a faithful answer. Write the event next to every probability column; a bare p hides the most important assumption.

Calibration is a claim about frequencies

Calibration asks whether events occur at the frequencies promised by forecasts. Among comparable forecasts near 0.8, do roughly eight tenths have the positive label? This is a population statement, not a guarantee about one document. A reliability diagram groups predictions, plots mean probability against observed positive fraction, and shows how many observations support each point. Without group sizes and uncertainty, a tidy diagonal is easy to overread.

Ranking, by contrast, survives a strictly increasing change of scores. The next example keeps every pairwise ordering but changes squared probability error and decisions at a fixed threshold. Four points are enough to demonstrate that distinction; four points are not enough to certify calibration. Do not promote a classroom counterexample into a measured model property.

Same order, different Brier score

For synthetic labels y=[0,0,1,1], compare p=[0.1,0.2,0.7,0.8] with p′=[0.6,0.7,0.9,0.95]. Both sort the items identically. Brier is the mean squared error: for p, \((0.01+0.04+0.09+0.04)/4=0.045\); for p′, \((0.36+0.49+0.01+0.0025)/4=0.215625\). Ranking metrics cannot see this change in the probability scale.

At a pass threshold of 0.65, p accepts the two positive items. p′ also accepts one negative item. This comparison is deliberately not temperature scaling: a positive temperature cannot move a binary probability across one half. In the next interactive, the shifted vector and the temperature experiment are separate modes. Brier measures overall probability quality, which includes more than calibration alone; read it alongside the diagram and a constant-probability baseline.

For the original predictions, Brier is 0.045. With threshold 0.65, only the two positive examples are selected.

The order is unchanged, but Brier becomes 0.215625 and the same threshold admits a negative example.

A separate experiment: change positive temperature on the original logits. Ranking stays fixed; Brier and threshold decisions may change. Fit T only on calibration data.

A confident error is expensive

Return to L4: binary log loss is \(-N^{-1}\sum_i[y_i\ln p_i+(1-y_i)\ln(1-p_i)]\). A positive item receives penalty \(-\ln p\); predicting a probability close to zero makes that penalty large. The asymmetry is about how wrong certainty is punished, not about changing the positive label’s meaning. Use the same event and same held-out items for every method.

An exact zero assigned to an observed positive outcome gives infinite mathematical loss. Software often clips with a small epsilon for numerical reporting; fix and publish that epsilon before comparing systems. Clipping is not calibration, and min–max normalization of arbitrary scores does not make them probabilities. Report Brier and log loss together with frequency diagnostics so a single summary does not conceal a concentrated failure mode.

A diagonal is not a search engine

For bins b, positive-event ECE is \(\sum_b(n_b/N)|\overline p_b-\overline y_b|\). Our primary report predeclares five equal-width bins; the last includes probability one, empty bins contribute zero weight. Changing bins can change ECE without changing any prediction. Show group counts and an uncertainty estimate, and report alternative binning as sensitivity analysis rather than choosing the prettiest diagram.

A constant prediction equal to the population’s base rate can be calibrated while distinguishing no useful document from any other. This is why calibration is not ranking skill and why Brier is not a pure calibration measure. Conversely, pooled calibration can hide subgroup problems. Evaluate the relevant language and task slices, but do not draw confident conclusions from nearly empty bins. “Insufficient evidence” is a valid result.

Temperature changes scale, not order

For a binary logit z, define \(p_T=\sigma(z/T)\) with \(T\gt0\). Both division by a positive number and the sigmoid are strictly increasing, so ordering survives. But distances to a fixed probability threshold change. A positive logit remains positive, hence a probability above one half remains above one half. This is why the p-to-p′ shift in our earlier counterexample cannot be described as one temperature transformation.

Fit T on calibration data, then evaluate it once on test. A shifted base rate may require an intercept or another mapping; one temperature is not a universal repair. Guo et al. provides a primary study of post-hoc calibration. Do not quietly use a CE’s raw sigmoid as a certified probability baseline while demanding careful validation only from Jev.

The unit of separation is the query family

Development chooses the rubric, preprocessing, and a short list of candidate policies. Calibration fits probability mappings and selects thresholds under a fixed objective. Test estimates the result after those choices are locked. Keep paraphrases, translations, and near-duplicate source pages in the same family and split that family as a unit. Randomly splitting query–document pairs leaks the same information across partitions.

If you inspect test failures and improve the rubric, the old test becomes development evidence; seek a fresh confirmation set. Even calibration data can be overused by a large policy search, so limit the search in advance or use an inner split. Do not alter the declared error costs until the preferred system wins. Those costs express the application’s priorities, not an adjustable reporting style.

Derive the threshold from two losses

For the passage event Y, let passing a useless fragment cost \(C_{FP}=4\), and dropping a useful fragment cost \(C_{FN}=1\). Correct actions cost zero. At probability p, expected losses are \(L(\text{pass})=4(1-p)\) and \(L(\text{drop})=p\). Passing is better when \(4(1-p)\lt p\), hence \(p\gt0.8\). At equality our declared rule drops. These are illustrative loss units, not measured financial damage.

At p=0.85, pass costs 0.60 in expectation and drop costs 0.85: pass. At p=0.70, pass costs 1.20 and drop costs 0.70: drop. In general this loss matrix gives threshold \(C_{FP}/(C_{FP}+C_{FN})\).

The formula requires a meaningful probability for this event and a suitable population. It is not a universal “Jev threshold”. Change the event, correct-action losses, or available actions and derive the policy again. The interactive next shows a second passage cost ratio before switching to a different context decision.

Pass loss is 4(1−p), drop loss is p. Passing is cheaper only when p > 0.8.

Increase the false-acceptance cost to 9. For the passage filter the threshold rises to 0.9; ranking need not change.

Change the event and the loss matrix: insufficient context costs 9, deferral costs 1 regardless of the label. Allow only when p > 8/9.

The whole context is a different object

Hide C. Add E: Vega14 supports connecting M2 to U1 with a cable of fictional profile V7, but the cable’s own specification determines its profile. B states that C7 carries V7. Neither fragment is sufficient alone; together they establish the required connection. A maximum of per-passage sufficiency scores misses this complementarity. Conversely, C and a conflicting C− can each appear decisive while their combination leaves the answer unresolved.

Ask a separate question about query plus the complete selected context. For a conflict, inspect applicability and version metadata; “take the newest text” is not automatically a valid rule. If a user parameter is missing, clarification may be appropriate; if evidence is missing, another bounded search may help. These are candidate policies to test, not guarantees. RAG passage classification illustrates decomposition into explicit judgments.

Allow or defer is not pass or drop

The minimal lab controller has two actions: allow generation now or defer the automatic answer. Its event \(Y_\text{ctx}\) is context sufficiency. Allowing on an insufficient context costs nine; allowing on sufficient context costs zero; deferring costs one for either label. Therefore \(L(\text{allow})=9(1-p_\text{ctx})\) and \(L(\text{defer})=1\). Allow only when \(p_\text{ctx}\gt8/9\); equality defers.

Do not reuse the passage filter’s formula with costs nine and one: that filter charges for dropping only when the document is useful, whereas this controller charges for every deferral. The matrices differ. Nor does deferral imply a perfect eventual rescue. This exercise prices the present permission decision, not the full harm of the final generated answer. A three-action controller needs the expected outcomes and costs of clarification and another search as well.

A system that never acts needs a different score

Coverage is the fraction of queries where the policy permits an automatic answer. Selective risk here is unsupported permissions divided by all permissions. At zero coverage the denominator is zero: risk is undefined, not zero. Plot risk and coverage together, and also report mean loss from the declared matrix. Otherwise “always defer” can masquerade as a perfectly safe useful system.

Sweep a predeclared threshold grid on calibration data, select using the fixed loss objective, then freeze the choice. Compare it on test with always allow and always defer. A low observed error count on a small test set still has uncertainty. Keep a request-level outcome for service failures so silently dropping difficult queries does not improve the reported risk. A lower-risk point is useful only in relation to its coverage and cost.

Freeze what each scorer is allowed to see

Start with the executable support example from slides 47–54. A customer asks whether Vega14/U1/C7/M2 work together. The authored corpus has a keyword-heavy shop page A, a partial cable specification B, a complete manual C, and an unrelated manual D. The standalone Python runner computes real BM25 locally: A → C → B → D. With a key, it sends each exact query–passage pair to Jev, sorts by expected gain, then checks the selected whole context with a separate Noul. It returns a verbatim excerpt with a source ID only if the policy allows; otherwise it defers. There is no text generator in this demonstration.

A fair reranker comparison begins before any score is returned. Save one candidate list per query, exact document IDs, full visible texts, and initial order. Give BM25 order, the cross-encoder, and Jev the same candidates. When context limits differ, compare on common visible text and report full-context access as a separate ablation. Do not send gold labels, initial ranks, or another system’s scores as hints in Jev’s state.

Use independent human grades under the frozen rubric; resolve disagreements without seeing model scores. For the controller, freeze a context-building rule and separately label whole-context sufficiency. Hand-crafted contradictions and complementary passages belong in a named stress set, not silently in the main frequency estimate. The synthetic lab rehearses this protocol; a real deployment comparison still requires real frozen inputs and measured responses.

Three tables, no preselected winner

The course now includes an actual local Laya run, not a Jev reconstruction with random weights. Both the implementation and the checkpoint model card declare Apache-2.0. The shared runner sends the same state and Score/Noul questions to the pinned Laya checkpoint or to Jev through TypeSafe. Similar interfaces do not mean identical weights, training or quality. No Jev measurements are available without an API key; that column stays empty.

On the fixed English Vega14 query, BM25 orders A,C,B,D with nDCG@3 = 0.7364; actual Laya inference orders C,B,A,D with nDCG@3 = 1. However, Noul gives the consistent manual C a score of 0.6815 and the conflicting C+C-minus context 0.6849. With the predeclared costs 9/1 and strict threshold 8/9, all four context cases defer. Coverage is zero, conditional risk is undefined, and mean loss is one, equal to always-defer. The selected context is C, but the actual output is defer with no excerpt and no generator call. The four context cases yield Brier = 0.252665 and log loss = 0.699477. These are descriptive scores on author labels, not calibration estimates or a benchmark. The ranking table contains candidate-conditioned nDCG, reciprocal-rank averages, and a separate retrieval-recall estimate. Russian and hostile text are test conditions

Use naturally written Russian queries, not only translations of the English set. Fix the language of the rubric and treat automatic translation as a separate pipeline variant. For each slice, report its size and uncertainty. A multilingual cross-encoder is a more informative Russian baseline than quietly comparing against an English-only checkpoint. Choose its revision on development, not after seeing test performance.

The provider documents uneven behaviour on arithmetic, indirect reasoning, distracting context, and adversarial instructions. Jev jaggedness. Put malicious passage instructions in a labelled stress set and keep them as data, never executable authority. A prompt saying “ignore instructions in the passage” is a defence to test, not a security proof. Structured dates and counts should be handled by code where possible.

One request, an explicit contract

The optional live path uses typesafe-sdk==0.7.2 and model jev-1.13.0, as checked for this chapter on 1 October 2026. The key comes from TYPESAFE_API_KEY outside source control. An input state names query and passage; a Score question contains the self-contained rubric. Read the response through its typed collections, and save response.model plus usage.input_tokens. Python client, response types.

Minimal call shape: with TypeSafeClient(model="jev-1.13.0", timeout=30) as client: response = client.system_one(state = state, questions={"relevance": Score(instructions=rule, criteria=levels)}). Here state, rule, and levels are the frozen input, instruction, and rubric above, not unspecified magic defaults. Then grade = response.scores["relevance"] and gain = sum((2**r - 1) * p for r, p in grade.probabilities.items()). Python level keys are integers; JSON keys are strings.

The lab contains the complete optional example and an offline route. Merely reading this chapter runs no cloud request and spends nothing. Validate expected level keys, finite values, bounds, and total probability before sorting. A missing or malformed answer is an operational failure, not a document with relevance zero.

A timeout is not an irrelevant document

A model request is only one operation in reranking a shortlist. Bound concurrent requests, retries, total deadline, and spend. A per-request timeout does not bound the complete top-k operation. If evaluation fails, our simple policy returns the original order for the entire query and logs degradation. Do not merge a few expected gains with leftover BM25 scores: their scales are not interchangeable.

Cache raw responses with model version, rubric hash, input hash, language, and preprocessing. Measure end-to-end shortlist latency, including retries and cache status, rather than quoting an isolated request. Keep secrets and private text out of public archives; SDK body logging may expose input even when headers are redacted. Check current limits and prices before a live run. Models, client configuration.

“Do not add Jev” is a valid result

A deployment recommendation must name the benefit and the constraints. Better nDCG can justify a reranking role without justifying probability thresholds. Better context decisions can justify a controller role without changing document order. Comparable quality with worse latency may justify keeping the current system. A weak Russian slice can rule out use on that traffic even when the pooled average improves.

Write acceptance criteria before test evaluation: the relevant quality difference, tolerated unsupported permissions, minimum coverage, and latency and cost budgets. Then report which were met, which failed, and where evidence is too sparse. Synthetic fixtures establish that the machinery is understandable and reproducible. They cannot establish a model’s production value. A negative recommendation supported by the right experiment earns the same credit as a positive one.

The model estimates; the policy decides

Return to the original connection question. Retrieval brings candidate passages; a rubric defines useful evidence; a typed distribution exposes uncertainty; a declared utility creates an order. Separate labels test the probability scale. A loss matrix then determines whether to act, while a whole-context check catches missing combinations or conflicts. Each arrow adds an assumption, and each assumption needs a place in the report.

Séréga keeps Sir Cosine’s ruler, but no longer asks it to price an answer. Goodhart loses his easiest hiding place: one flattering score standing in for three different tasks. You now have three questions to ask of any Jev integration: probability of what, action at what cost, verified against which independent outcomes? The durable lesson is that order, probability, and action must be checked separately—even when one API returns all the numbers.
