Never edit the assembled `Lectures/NN-*.html` (it's gitignored build output and gets overwritten). - **Change one number:** edit `data/<file>.json` (the source); re-run its generator and prove H3 byte-identity with `bash _research/reproduce.sh`; `check_claims` enforces deck==data, Book==data, AND (coverage-guard `[G]`) that no NEW displayed number is un-gated. The number is also hand-typed prose at each display site — `git grep` it across the deck + Book to update all copies (a new display site must be gated or it HARD-fails the coverage-guard).
- **Add a widget:** create `widgets/<name>/{logic.js,manifest.json,i18n.json,style.css}` — auto-discovered by Book, Playground, and `widget-render-check`.
- **Mount a widget ON A SLIDE — the deck side is NOT auto-discovered.** Three things must line up or the slide ships BLANK: (1) the mount `<div class="widget-mount" data-widget="<id>">` plus its `<script class="widget-data">` in the fragment; (2) the id in `DECK_WIDGETS` in `scripts/build-deck-widgets.mjs` (bundles `Lectures/js/<id>.classic.js`); (3) **a `<script src="js/<id>.classic.js"></script>` in THAT deck's `parts/zz-tail.html`** — this one is per-deck and hand-written. Five course-map slides shipped blank on 2026-08-19 because only (1) and (2) were done, and **every gate stayed green**: composition sees no overflow where there is no content, and the image checks only look at `<img>`/`<image>`. `viz-probe` now HARD-fails an empty mount (`WIDGET NOT MOUNTED`) — but the cheapest check is still `--contact` and your own eyes. A fourth way to ship blank, found by that new check: **`exportName` in `logic.js` must be `mount` + PascalCase(id) exactly** — the adapter looks up `window[mountName(id)]` and nothing else. `bpe-merge-ledger` registered itself as `mountBpeLedger` (no *Merge*), so slide 27a of deck 02 had been shipping empty for who knows how long, in the deck AND its contact sheet, unnoticed by every gate.

Registries are glob-driven — `BOOK_READY`, `check_claims DECKS`, `wbw-check`, `responsive-gate`, book route, beat/scroll/i18n gates all auto-discover. (Curated `slide-viz` `DECK_TARGETS`/`BOOK_TARGETS` are optional per-figure defect targets, not per-unit registration.) **Illustrations:** add the briefs to `_research/gen_images.py` `JOBS` reusing the `mascots.py` cast — Séréga must appear in ≥40% of plates AND in the hero + final plate (the image-gate enforces this; don't ship Séréga-less abstract plates). Generate with `python3 _research/gen_images.py L7`.
- **Add homework/seminar:** `src/lib/assignments.js` — content-first, ~0 plumbing (the reference model).
- **Seminar artifacts live on Drive** (`/content/drive/MyDrive/dls-2026/artifacts`, rule 10.4): the chain `bm25_index.json → metrics.py → cascade.json → corpus_emb.npy` is what makes lesson N+1 run at full scale, and the Colab sandbox dies with the session. **G24 now HARD-fails a notebook that touches ARTIFACTS without mounting Drive** — the rule sat in the standard for months while all seven notebooks wrote to `./artifacts`, and nothing said a word. Run archives carry only `<name>.json` + `run_log.txt` (~5 KB); the chain files stay out of them on purpose, since `files.upload()` (§10.1) makes putting them back impossible anyway.
- **Re-run the seminars (owner-only, needs a GPU):** `python3 scripts/sync_solved.py` builds the solved copies in gitignored `tmp/colab-t4/` (grafting the solutions out of the previous copies — never re-type them). Each notebook's LAST cell zips its run — `<name>.json` (metrics + runtime) plus `run_log.txt` (the whole session's prints) — and renders a `data:` download link; `python3 scripts/import_runs.py --gate` then takes those archives out of `~/Downloads`, routes each dump BY ITS OWN `runtime.gpu` (accelerator → `seminars/runs-t4/`, CPU → `seminars/runs/`, so a T4 run can't overwrite the baseline it is compared against), files the logs under `seminars/runs/logs/`, and runs G29. **The log hook is not a `Tee`:** replacing `sys.stdout` makes ipykernel drop every cell's output on the floor, and a one-shot `write` patch dies after the first cell because IPython re-wraps `write` per cell — so the notebooks re-arm the patch on `pre_run_cell`. **Driving it from the `colab` CLI (2026-09-03): pull each archive down the moment its notebook exits, never at the end of a queue.** A lost session takes its VM's sandbox with it — and worse, the CLI's cleanup wipes the name→endpoint registry, so the VM keeps running while nothing can reach it: `dls_cpu` died mid-`hw-alliance` and took the finished `lab-cascade` archive with it. Both `exec` and `download` **exit 0 on that failure** (`Session 'x' not found.` on stdout), so a queue happily reports success having run nothing — check the output text, not the exit code. The dump collector is also what decides whether G29 has anything to compare: it must reach RUN, whose keys carry the units the prose actually prints. **CPU-базы для `lab-ann`, `hw-rag` и `project-search` не сняты, и это решение, а не недоделка (2026-09-04).** Четыре захода: три умерли обрывом сессии на длинном прогоне (`hw-alliance`, затем `hw-rag`), четвёртый — с отдельной сессией на тетрадку и без подготовительной цепочки (`hw-rag` её не читает, `lab-ann` создаёт `corpus_emb.npy` сам, `project-search` проверяет мягко) — показал настоящую причину: `hw-rag` считал ОДНУ ячейку 3.5 часа и не кончил. На T4 та же тетрадка отрабатывает за минуты; на CPU её кодирование корпуса медленнее в десятки раз, а `lab-ann` там ещё и строит FAISS с PQ. Полный набор CPU-баз стоит от полусуток до суток счёта. Владелец прервал — цена не сходится. Следствие: `[T4]` сверяет качество строго для четырёх тетрадок, а для этих трёх ПРОПУСКАЕТ с WARN «в локальной базе нет RUN». Непроверенное помечено непроверенным; не переоткрывать без GPU-базы или сокращённого корпуса.

## Что сознательно НЕ гейтится (и почему — не переоткрывать)
- **Провенанс квалификаторов (план 4.5).** Замысел: пометка «игрушечный пример / относительные
  проценты / GPU-батч» обязана стоять на том же слайде, где показано число. Проверены три
  формулировки, все — театр: (1) «число совпало со значением из toy-файла» → 223 слайда, среди них
  √2 и параметр `b` BM25; (2) то же с уникальной принадлежностью значения одному файлу → 37, но
  ручная проверка первого же (`L18 · 06 Hook`) показала, что там числа **из статьи Günther 2024**,
  а совпадение случайно; (3) «слайд-разбор с числами обязан нести слово-оговорку» → 22 из 28, и это
  слайды вроде «BM25 на кошках и собаках», где корпус из трёх документов виден глазами. Причина
  общая: происхождение числа не выводится из его значения, потому что одни и те же величины
  приходят и из статей, и из игрушечных расчётов. Надёжный гейт возможен только если у claim'ов
  в `check_claims.py` появится ЯВНОЕ поле провенанса (515 записей, 14 реестров) — до тех пор
  проверки нет, и это лучше, чем 37 «нарушений», которые все научатся пролистывать.
- **«Акт закрывается слайдом-границей» (часть плана 4.8).** Правило есть в Definition of Done, но
  его не проходят эталонные деки 10 и 12 (7 актов из 8 и 4 из 5): акты закрываются содержательным
  слайдом, а не служебным ярлыком. Убрано из G34 после замера — см. коммит гейта.

## Definition of Done for a lecture — gates are the FLOOR, L10–L12 are the BAR
**Green gates mean "no regression in correctness" — they do NOT mean "good."** The bar is: *indistinguishable from L10–L12 in depth + polish, proven by LOOKING at the rendered slides.* A lecture is born to this bar, never rebuilt to it. Before calling a deck done, every box must be ticked:
- [ ] **Depth ≥ ~50 slides** (L10–L12 = 50–63), one idea per slide, full scaffolding (you-are-here · agenda · objectives · per act: divider → hook → problem → formal → climb-widget → worked-by-hand → real example → frontier → boundaries · synthesis · references). **Build FROM the reference deck's structure, not from scratch.** → `node _audit/parity-gate.mjs` (**G18**).
  **Дека 00 — намеренное исключение (решение владельца, 2026-09-05).** 26 слайдов при пороге 45, и доращивать её не нужно: это вводное занятие про логистику, оценивание и инструменты. `mechanism-gate` уже освобождает её от требования учебного механизма («требовать его — значит требовать формулу про расписание»); то же основание действует и для глубины. Не переоткрывать.
- [ ] **No walls of text** — median ≤ ~1150 visible chars/slide; use def-cards / formula-stages / cmp-tables / images, never paragraphs. → parity-gate (**G18**).
- [ ] **Illustrations actually generated** — every `gen_images.py` brief → a committed PNG, every referenced image exists on disk, made with the course's reference model **`nano-banana-pro`** (not gpt-image-1). → `python3 _research/check_assets.py` (**G17**) + brand `check_images.py` (**G12**).
- [ ] **Composition holds** — no slide content overflows/clips the 1920×1080 frame. → `node _audit/composition-gate.mjs` (**G19**) + `slide-viz-gate.mjs` (**G9**) for figures.
- [ ] **Readable — scale + no collisions** — масштаб: no PROSE authored below the floor (deck 11px / book 12px raw); наложения: no figure-label collision ≥50%. → `node _audit/readability-gate.mjs` (**G20**) + `node _audit/viz-probe-gate.mjs` (**G13**, severe overlap now HARD). Figures fit-scale by design; their legibility is G9/G13's, not a raw-font concern.
- [ ] **Auto-fit ≥ 0.65, and never below 0.62** — `legibility-gate` (**G22**) HARD-fails under **0.62** and WARNs in the **0.62–0.65** band, because a slide authored at 0.61 passes on macOS and fails on CI's Linux (it did, twice). Aim for the target, not the floor. Sub-16px labels INSIDE figures are ratcheted by `viz-probe` against `_audit/baselines/viz-tiny-text.json`: NEW or WORSE is HARD. **Both baselines may only shrink, and this is now mechanical, not a promise** — `--update-tiny-baseline` / `--update-baseline` REFUSE to write a re-freeze that adds an entry or worsens one, and `viz-probe` exits 1 if its baseline file is missing/corrupt (that file is the ratchet's arming pin: deleting it used to drop the whole rule back to WARN).
  **Two levers, learned by raising seven slides out of the band (2026-08-19) — neither is obvious:**
  (1) In `slide-header--flush` the header's height is the height of **`h2` alone**, not `h2 + kicker` — they sit side by side. Trimming the kicker buys 0 px; pulling `h2` from two lines onto one buys **−72 px** at a stroke. Cut the headline first.
