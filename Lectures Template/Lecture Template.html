Ключевой термин Key term

Definition
Определение Definition
Градиентный спуск Gradient Descent gradient descent · GD

Итеративный алгоритм минимизации функции L(θ), на каждом шаге сдвигающий параметры против градиента:

An iterative algorithm for minimizing a function L(θ) that, at each step, moves parameters against the gradient:

$$\theta_{t+1} \;=\; \theta_t \;-\; \eta\, \nabla_\theta L(\theta_t)$$

где η — скорость обучения (learning rate), ∇L — градиент функции потерь. where η is the learning rate and ∇L is the gradient of the loss.

Слайд определения. Один термин, по-русски и по-английски. Старайтесь давать одно определение на слайд — не перегружать.

Сходимость на выпуклых функциях Convergence on convex functions

Theorem · 1.1
Теорема 1.1 · L-гладкость + выпуклость Theorem 1.1 · L-smooth + convex
Пусть L — выпуклая, L-гладкая функция, и η ≤ 1/L. Тогда после T шагов градиентного спуска: $$L(\theta_T) - L^* \;\le\; \frac{\|\theta_0 - \theta^*\|^2}{2\eta T}.$$ Let L be a convex, L-smooth function and η ≤ 1/L. Then after T steps of gradient descent: $$L(\theta_T) - L^* \;\le\; \frac{\|\theta_0 - \theta^*\|^2}{2\eta T}.$$
Идея доказательства Proof sketch
Из L-гладкости следует спуск на каждом шаге: $$L(\theta_{t+1}) \le L(\theta_t) - \tfrac{\eta}{2}\|\nabla L\|^2.$$ Суммирование по t и телескопирование даёт оценку. Скорость O(1/T) медленная — поэтому существуют ускоренные методы. L-smoothness implies descent at each step: $$L(\theta_{t+1}) \le L(\theta_t) - \tfrac{\eta}{2}\|\nabla L\|^2.$$ Summing over t and telescoping gives the bound. The O(1/T) rate is slow — hence accelerated methods exist.
Теорема + доказательство. Цветовая маркировка: синий = теорема, фиолетовый = лемма, зелёный = следствие, серый = доказательство.

Минимальная реализация на PyTorch Minimal PyTorch implementation

Python · PyTorch
Python · gradient_descent.py PyTorch 
import torch

def train_step(model, batch, optimizer, loss_fn):
    optimizer.zero_grad()

    # Forward — compute predictions
    preds = model(batch.x)
    loss  = loss_fn(preds, batch.y)

    # Backward — compute ∂L/∂θ for every θ
    loss.backward()

    # Update: θ ← θ − η · ∇L
    optimizer.step()
    return loss.item()

Под капотом optimizer.step() делает именно то, что записано в формуле выше. Under the hood, optimizer.step() performs exactly what the formula above says.

$$X \in \mathbb{R}^{T \times d}$$

Вход: матрица токен-эмбеддингов размера T × d. Input: token-embedding matrix, shape T × d.

$$Q = X W_Q,\ \ K = X W_K,\ \ V = X W_V$$

Три разные обучаемые матрицы дают Q, K, V — каждая со своей ролью. Three distinct learned matrices produce Q, K, V — each plays a different role.

В реальной модели параллельно \(h\) голов, каждая с своими \(W_Q, W_K, W_V\). A real model runs \(h\) heads in parallel, each with its own \(W_Q, W_K, W_V\).

$$Q, K, V \in \mathbb{R}^{T \times d_k}$$

Q — что мы ищем, K — что у нас есть, V — что отдаём. Q — what we look for, K — what we have, V — what we return.

$$S = Q K^\top \in \mathbb{R}^{T \times T}$$

Скоры внимания: dot-product между каждой парой токенов. Attention scores: dot-product between every pair of tokens.

В decoder'е здесь применяют causal mask: \(S_{ij} = -\infty\) при \(j > i\). In decoder models a causal mask is applied here: \(S_{ij} = -\infty\) for \(j > i\).

$$\tilde S = S / \sqrt{d_k}$$

Масштабируем — чтобы softmax не насыщался при больших \(d_k\). Scale down so softmax doesn’t saturate at large \(d_k\).

$$A_{ij} = \dfrac{e^{\tilde S_{ij}}}{\sum_k e^{\tilde S_{ik}}}$$

Softmax построчно — \(A_i\) становится распределением по \(T\) токенам. Row-wise softmax — \(A_i\) becomes a distribution over \(T\) tokens.

$$Z = A V \in \mathbb{R}^{T \times d_k}$$

Взвешенная сумма V по весам внимания. Weighted sum of V using attention weights.

$$Z' = Z W_O$$

Output-проекция возвращает в размерность \(d\) (для multi-head: concat голов перед \(W_O\)). Output projection brings us back to dimension \(d\) (for multi-head: concat heads first, then \(W_O\)).

$$\mathrm{Out} = X + Z'$$

Residual connection: добавляем вход обратно. Критично для потока градиентов — без него глубокие трансформеры не обучаются. Residual connection: add the input back. Critical for gradient flow — without it deep transformers don’t train.

$$\mathrm{Out} = \mathrm{LN}(X + Z')$$

Нормализуем после residual — это post-LN (оригинал Vaswani et al.). Современные модели (GPT, LLaMA) используют pre-LN: нормализуют до attention, \(x + \mathrm{sublayer}(\mathrm{LN}(x))\), не трогая residual — так обучение стабильнее. We normalize after the residual — this is post-LN (Vaswani et al. original). Modern models (GPT, LLaMA) use pre-LN: normalize before attention, \(x + \mathrm{sublayer}(\mathrm{LN}(x))\), leaving the residual un-normalized — trains more stably.

Каждая ячейка \(E_{ij}\) — похожесть запроса \(i\) с ключом \(j\) (scaled dot-product). Матрица \(T\times T\).Each cell \(E_{ij}\) — similarity of query \(i\) with key \(j\) (scaled dot-product). A \(T\times T\) matrix.

Веса вниманияAttention weights
$$A_{ij}=\dfrac{e^{E_{ij}}}{\sum_{k} e^{E_{ik}}}$$

Softmax по строкам: каждая строка \(E\) → распределение внимания, \(\sum_j A_{ij}=1\) (подсвечена строка 1).Softmax over rows: each row of \(E\) → an attention distribution, \(\sum_j A_{ij}=1\) (row 1 highlighted).

Распространённое заблуждение Common misconception

Bust the myth
Что думают студенты What students think

«Attention — это просто dot-product Q и K. Зачем три матрицы?» “Attention is just dot-product of Q and K. Why three matrices?”

Три проекции дают разным токенам асимметричные роли: что я ищу (Q), что у меня есть (K), что я отдаю (V). Без них attention был бы симметричен (S = ST) и эквивалентен PCA-проекции. Информационная асимметрия — это и есть «внимание». Three projections give tokens asymmetric roles: query, key, value. Without them attention would be symmetric (S = ST) and equivalent to a PCA projection. That asymmetry IS attention.
Use this slide BEFORE explaining the multi-matrix attention. Get the misconception out loud, then bust it.

Residual connections — костыль Residuals are a hack

Они скрывают, что сеть не может научиться identity-мэппингу самостоятельно. NormFormer, RealFormer, GhostNet ищут альтернативы. Может, нам нужны не residuals, а лучшая инициализация и регуляризация. They hide that the network can’t learn identity on its own. Maybe what we need is better init and regularization, not residuals.
