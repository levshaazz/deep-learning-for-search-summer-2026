# Lecture Template — CS / DS / ML / DL / NLP

Темплейт интерактивных презентаций для лекций по Computer Science. Рассчитан на проекцию в лекционной аудитории (1920×1080), с богатым набором lecturer-tools для живой подачи материала.

---

## 🚀 Quick start: создать новую лекцию за 10 минут

```bash
# 1. Скопировать темплейт под новую лекцию
cp -r "Lecture Template/" "Lectures/CS-310 Lecture 06 - Backpropagation/"
cd "Lectures/CS-310 Lecture 06 - Backpropagation/"
mv "Lecture Template.html" "Lecture 06.html"
```

Открой `Lecture 06.html` в редакторе и поменяй:

| Что | Где |
|---|---|
| Название лекции | `<section data-type="title">` → `<h1>` |
| Номер лекции, дата, лектор, аудитория | `<section data-type="title">` → `.title-footer` |
| Курс (для футера/хлебных крошек) | `<div class="slides" data-course-ru="…" data-course-en="…">` |
| Логотип | `<template id="tpl-logo">` |
| Содержимое слайдов | `<section data-type="…">` блоки |
| Заметки лектора | `<aside class="slide-notes">…</aside>` внутри каждого слайда |

Открой `Lecture 06.html` в браузере — готово.

## 🎨 Каталог типов слайдов

Все ~29 типов лежат в `Lecture Template.html` как живой пример. Базовые 17 описаны в таблице ниже; дополнительно есть `objectives` (цели обучения), `e2e` (синхронизированный forward-pass), `archflow` (пошаговый reveal сложной архитектуры + **режим системного блюпринта**, см. ниже), типы для **ML System Design** — `funnel` (сужающийся каскад) и `sequence` (поток запроса + бюджет задержки), и «лабораторные» `misconception`, `derivation`, `pause`, `reverse`, `forward`. Каждый слайд:

> **`archflow` — пошаговая сборка сложной архитектуры (вектор, без растровых кадров).**
> Диаграмма рисуется ОДИН раз позиционированными узлами (`.af-node` в координатном холсте 1000×600); правая панель синхронно показывает формулу (KaTeX) и двуязычную подпись. Управление — штатным степпером (`data-max-step`, `←/→`, deep-link `#/N/M`). Всё векторное → тема/RU-EN/доступность/чёткость/единый источник правды. Используйте вместо экспорта N почти одинаковых картинок.
>
> **Стандартизованный контракт (v2):**
> • `.af-node id="…"` — узел; `id` **обязателен** (на него ссылаются стрелки). Позиция — `left/top` % (центр). Контент: KaTeX-символ, матрица (`.af-matrix` + `.af-cell`) или **реальное изображение** (`data-role="image"` + `<img alt>` — вход/feature-map; `src` можно заменить на свой PNG).
> • `.af-edge data-from-node data-to-node` — **декларативная стрелка**: движок сам прокладывает путь между якорями узлов (никаких ручных координат, которые «уезжают»). `data-from-anchor`/`data-to-anchor` ∈ `left|right|top|bottom|auto` выбирают сторону входа/выхода. Пересчитывается при resize/типографике → всегда корректна и в масштабе.
> • `data-from="k"` — появиться на шаге `k` (накопительно). `data-focus="k"`/`"a..b"` — рамка-фокус `.af-focus` едет к элементу. `.af-note[data-step="k"]` — пояснение шага (показывается текущее).
> • SVG-слой стрелок строит движок — авторам SVG писать **не нужно**.
>
> **Режим системного блюпринта (`archflow`)** — для ML System Design. Тот же движок + : **swim-lanes** (`.af-lane[data-lane="offline|online"]`) и **группы** (`.af-group`); рёбра с **подписями** (`data-label`) и **типами** (`data-kind="async"` → пунктир); **роли system-design** (`source/pipeline/store/serving/external/monitor`) + **авто-легенда** (`.af-legend[data-auto]` — движок генерит из ролей/типов, практика C4). Пример — продакшн-recsys (offline ↔ online, Feature Store, петля обратной связи).
>   • **Авто-раскладка** (`data-layout="grid"` на `.af-canvas`): узлы с `data-lane`+`data-col` ставятся на ровную сетку внутри лейна — без ручных %, без наложений при смене шрифта/темы (узлы без `data-lane` оставляют явные `left/top`).
>   • **Ортогональный роутинг** (`data-routing="orthogonal"`): рёбра — Manhattan-ёлочки сквозь каналы сетки (стиль C4). Per-edge `data-route` переопределяет: `curved` | `orthogonal` | **`around`**.
>   • **Обратные рёбра** (feedback / back-edges) — по **периметру кластера узлов** (поле за пределами всех узлов; координаты из bbox → не пересекают узлы/прямой поток, без ручной подгонки). В orthogonal-режиме движок **авто-детектит** их (target сильно выше по потоку — далеко слева) и сам ставит `around` — `data-route` указывать не нужно (явный `data-route` всё равно переопределяет). Несколько параллельных петель **разводятся по вложенным дорожкам** периметра (channel-глубина + сдвиг точек входа/выхода) — не накладываются друг на друга. `data-around="top|bottom"` выбирает канал. Общее масштабируемое решение пересечений петель.
>   Геометрию (наложения, **пересечение подписей/рёбер с узлами**, выход за холст) проверяет `_audit/archflow-audit.mjs`.

> **`funnel`** — многоступенчатый каскад, сужающийся от миллионов к десяткам (`.funnel-stage[data-step]`, ширина `--w`; чистый CSS на штатном степпере). Для retrieval→ranking→re-rank.
> **`sequence`** — поток запроса по lifelines (`.seq-actor[data-actor]`) с упорядоченными сообщениями (`.seq-msg[data-step][data-from][data-to][data-lat]`) и **бегущим бюджетом задержки** (`data-budget`; итог краснеет при превышении SLA). Движок — `js/sequence.js`. Геометрию (наложения чипов/подписей, выход за холст, бюджет = сумме шагов) проверяет `_audit/sequence-audit.mjs`. Для serving/latency.

> **Проверки (две линии + негативные тесты):** живой pre-flight (`js/preflight.js`) ловит структурные ошибки в браузере (битые ссылки стрелок, шаги вне `[0,max]`, картинка без `alt`, шаг без заметки); headless-аудит `_audit/archflow-audit.mjs` гоняет **геометрию на каждом шаге** (пересечения узлов/подписей, стрелки реально касаются своих узлов, ничего не выходит за холст). У аудита есть режим `--break=overlap|offcanvas|dangling|range|alt` — намеренно ломает пример (для демонстрации/отладки). Регрессионные **негативные тесты** `_audit/archflow-negative.mjs` инъецируют каждый дефект, проверяют, что он **пойман**, и что дек снова чист после отката. Обе проверки + негативные тесты стоят в CI.

> **`reverse` ↔ `forward` — послойный разбор сети, один движок, два направления повествования.**
> Оба используют общую разметку (`.reverse-stack` / `.reverse-layer[data-layer="0..N"]`) и единый степпер: внутренний шаг — это «прогресс рассказа» `0..N`, **`→` всегда вперёд, `←` назад, старт с шага 0**.
> • `forward` — шаг `k` показывает слой `k` (input → … → result, «строим снизу вверх»). Открывается на входе.
> • `reverse` — шаг `k` показывает слой `N−k` (result → … → input, «как мы сюда пришли»). Открывается на финальном результате, но `→` корректно отматывает к истокам и **не выкидывает со слайда** раньше времени.
> Выбирайте направление под нарратив лекции; `←`/`→` ведут себя одинаково (вперёд/назад по рассказу) в обоих.

```html
<section class="slide" data-type="<тип>" data-screen-label="NN Название">
  …контент…
  <aside class="slide-notes">Заметка лектора (поддерживает HTML).</aside>
</section>
```

## 🌍 Двуязычность

Контент пишется параллельно в одном слайде:

```html
<h2>
  <span lang="ru">Сходимость на выпуклых функциях</span>
  <span lang="en">Convergence on convex functions</span>
</h2>
```

CSS прячет неактивный язык. Переключение по клавише `L` или через тулбар. Технические термины (PyTorch, gradient descent, etc.) остаются на английском.

**Правило:** один `<span lang="ru">` + один `<span lang="en">` рядом для любого мульти-язычного текста. Никаких отдельных «русской» и «английской» версий слайдов.

## 🎨 Кастомизация

### Цветовая палитра и шрифты

Все токены — в `css/template.css` `:root`. Чтобы поменять акцентный цвет под бренд курса:

```css
:root {
  --accent: #C9447A;       /* был синий, стал розовый */
  --accent-ink: #8A2050;
  --accent-soft: #F6DCE5;
}
```

### Логотип

Шаблон логотипа в `<template id="tpl-logo">` в начале `<body>`:

```html
<template id="tpl-logo">
  <div class="logo-mark">CS</div>   <!-- 2-3 буквы или SVG-иконка -->
  <span>
    <span lang="ru">КАФЕДРА · CS DEPT</span>
    <span lang="en">CS DEPARTMENT</span>
  </span>
</template>
```

`.logo-mark` — квадратный блок 36×36; можно заменить на `<img src="logo.svg">`.

### Тёмная тема

Все цветовые токены продублированы под `:root[data-theme="dark"]`. Переключается клавишей `D` или через тулбар. Состояние запоминается в `localStorage`.

## 📐 Auto-fit / зачем слайды не выпадают за пределы

Контент каждого слайда оборачивается JS в `.slide-body`. На каждой смене слайда измеряется `scrollHeight × scrollWidth` и, если контент больше доступной площади (1920−240 × 1080−176), применяется `transform: scale(s)` с `transform-origin: top left` и компенсирующий `width: (100 / s)%`.

- **Минимальный scale**: 0.5. При scale < 0.65 в консоль идёт warning «контент плотный, подумайте о разбиении», и pre-flight показывает значок-предупреждение.
- **Обрезка контента**: если слайд не помещается даже при 0.5× (его нельзя ужать сильнее), лишнее **обрезается** (`overflow: hidden`). Это уже не «мелко», а «не видно» — поэтому такой слайд помечается как **ошибка** pre-flight (`data-auto-fit-clipped`), панель проверки **открывается автоматически**, и в консоль идёт `console.error`. Разбейте слайд на несколько.
- **Отключить fit**: `<section class="slide" data-fit="off" …>` — например, для viz-слайда со скроллом.
- **MathJax / KaTeX**: auto-fit перезапускается после окончания типографики (формулы могут вырасти).

## 🧮 Математика (KaTeX)

Inline: `\( x = 1 \)`. Display: `$$ \theta_{t+1} = \theta_t - \eta \nabla L $$`.

KaTeX типографирует синхронно при загрузке страницы. Покрывает 99% LaTeX-команд, нужных для CS/ML лекций. Если нужны экзотические команды (`\xymatrix`, кастомные пакеты), вернись к MathJax: найди в `<head>` блок «KaTeX» и замени его на:

```html
<script>
  window.MathJax = {
    tex: { inlineMath: [['\\(', '\\)']], displayMath: [['$$', '$$'], ['\\[', '\\]']] },
    svg: { fontCache: 'global' }
  };
</script>
<script src="https://cdn.jsdelivr.net/npm/mathjax@3.2.2/es5/tex-svg.js" async></script>
```

CSS поддерживает оба варианта (`.katex` и `mjx-container`).

## 🖨️ Печать / PDF export

`Cmd+P` (Mac) или `Ctrl+P` (Windows) в браузере. Каждый слайд печатается на отдельной странице (landscape, 1920×1080). Тулбар, прогресс, заметки, pen-layer скрыты. Скрытые ответы (`<details>`) автоматически разворачиваются — годится для раздаточных материалов.

Для standalone HTML-файла (отправить студентам без зависимостей):

```bash
node build-vendor.mjs       # 1) один раз: скачать KaTeX/Prism/QR/шрифты в vendor/ (нужна сеть)
node build-standalone.mjs   # 2) собрать один файл из vendor/ (сети НЕ требует)
# → "Lecture Template (Standalone).html"
```

Скрипт инлайнит ВСЁ в один файл: локальные css/js, KaTeX (+его шрифты),
Prism (core + python/bash/yaml/json), qrcode-generator и веб-шрифты Google
(woff2 → base64). Результат работает **полностью офлайн** — ноль сетевых
запросов (проверено Playwright'ом с полностью заблокированной сетью:
математика рендерится, шрифты грузятся, QR строятся, 0 внешних запросов).
Нужна сеть только на этапе сборки. Ограничение: подсветка кода офлайн только
для python/bash/yaml/json (autoloader для длинного хвоста языков отключён —
его грамматики нельзя скачать без сети).

> ⚠️ **Две фичи остаются ОНЛАЙН-ОНЛИ даже в standalone**: `<arxiv-quote>`
> (тянет аннотацию через `fetch` к `export.arxiv.org`) и Pyodide-раннер
> (`.pyodide-runner`, грузит интерпретатор Python с CDN, ~десятки МБ). В
> дефолтном деке они не активны (arxiv-quote закомментирован, runner'ов нет),
> поэтому офлайн-гарантия держится. Но если вы их включите — standalone снова
> начнёт ходить в сеть. Сборщик теперь это явно печатает: ищите в выводе
> `node build-standalone.mjs` строку `NOTE: runtime-fetchable URLs remain`.
>
> 🔒 **Безопасность Pyodide.** Раннер выполняет произвольный Python из
> `contenteditable`, поэтому:
> - `<script>` Pyodide запинён на `v0.26.4` и защищён **Subresource Integrity**
>   (`integrity="sha384-…"` + `crossorigin="anonymous"`) — подменённый ответ CDN
>   будет отвергнут браузером. При смене версии хэш нужно пересчитать:
>   `curl -fsSL <pyodide.js URL> | openssl dgst -sha384 -binary | openssl base64 -A`.
> - Перед **первым** запуском показывается одноразовый `confirm()`-баннер
>   (RU/EN): он предупреждает, что качаются десятки МБ с CDN, выполняется
>   недоверенный код и нужна сеть (offline ломается). Без согласия код не
>   запускается.
> - `<arxiv-quote>` — это динамический `fetch()`, к нему SRI неприменим (тело
>   ответа не фиксировано), поэтому весь возвращённый XML экранируется
>   (`escapeHtml`) перед вставкой и трактуется как недоверенный. Тоже не работает
>   offline.

## 🔗 URL routing

- `#/5` — слайд 5.
- `#/7/3` — слайд 7, шаг 3 (для walkthrough/e2e). Можно поделиться конкретным моментом.
- При перезагрузке страница откроется на том же месте (шаг применяется до первой отрисовки).
- **Back / Forward браузера** переключают между уже посещёнными слайдами: каждая навигация по слайдам пишет новую запись в `history` (`pushState`); смена шага внутри слайда — `replaceState`, чтобы не засорять историю.
- Кнопка «поделиться» — браузерный URL.

## 🖨️ Конспект (handout export)

- `?handout=1` — открывает **линейную версию для печати**: один прокручиваемый
  документ, где для каждого слайда выводятся заголовок, заметки лектора
  (`aside.slide-notes` + per-step `data-notes-for-step`), раскрытые скрытые
  ответы (`details.hidden-answer`) и разбор заблуждения (`.misc-truth`).
- Хром слайда, трансформации и анимации убраны — документ дружит с **Cmd+P**
  (печать/PDF). Печатается на одном языке (по `data-lang`).
- Реализовано в `js/handout.js` (читает существующий DOM, не мутирует дек);
  стили — в блоке `.handout-doc` в `css/template.css`.
- Пример: `Lecture Template (Standalone).html?handout=1`.

## ⚠️ Известные ограничения

- **Mobile**: темплейт оптимизирован для проектора 1920×1080. На экранах < 640px показывается warning. Свайпы работают, но текст мелкий.
- **MathJax / KaTeX**: формулы рендерятся синхронно. Очень длинные документы с десятками формул могут открываться 1-2с.
- **Print fidelity**: проверено на Chrome 120+. Safari может рендерить чуть иначе (особенно letterspacing).
- **Pen annotations** — рисунки не сохраняются между сессиями браузера.
