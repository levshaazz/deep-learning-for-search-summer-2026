# Colab-рантайм для сессий Claude Code (Deep Learning for Search)

## Право и дисциплина (сначала это)

- Правило №10: счёт на ЛОКАЛЬНОЙ машине запрещён ассистенту. Поправка от 04.09: счёт на
  VM Google Colab через официальный CLI — РАЗРЕШЁН.
- **CPU-сессии — свободно. Любой GPU (`--gpu ...`) — только после явного «да» владельца
  на конкретный запуск**, с оценкой стоимости (A100 ≈ 6–12 compute units/час; целевой
  R14-прогон стоил ~6 минут).
- Неостановленная сессия жжёт units до 24 ч. После работы: `stop` + проверить `sessions`.
- Каждый прогон, чьи числа могут попасть в статью, оформляется по циклу проекта:
  артефакты → `analysis/data/<ИМЯ_ПРОГОНА>/` → коммит зонтика → факт в FINDINGS.md.

## Канонический цикл (копируй и подставляй)

```bash
export PATH="$HOME/.local/bin:$PATH"
S=имя_сессии   # всегда именовать явно

# 1. Аллокация (CPU; для GPU добавь --gpu A100 ТОЛЬКО после «да» владельца)
colab --auth=adc new -s $S

# 2. Доставка кода: git-архив нужной ветки → /content (НЕ в подкаталог!)
git -C <репозиторий> archive --format=tar.gz -o /tmp/repo.tar.gz <ветка>
colab --auth=adc upload -s $S /tmp/repo.tar.gz /content/repo.tar.gz
echo "
import tarfile, os
tarfile.open('/content/repo.tar.gz').extractall('/content')
print('пакет виден:', os.path.isdir('/content/src'))
" | colab --auth=adc exec -s $S --timeout 300

# 3. Исполнение. ВСЕГДА --timeout (дефолт 30 с/ячейку убьёт любой счёт):
colab --auth=adc exec -s $S --timeout 5400 -f МОЙ_НОУТБУК.ipynb
#   .ipynb читается ЛОКАЛЬНО, исполняется в удалённом ядре, исполненная копия
#   *_output.ipynb пишется ЛОКАЛЬНО рядом с исходником — это провенанс-свидетельство.
#   Долгие прогоны — фоном (run_in_background), не sleep-поллингом.

# 4. ВОЗВРАТ АРТЕФАКТОВ — строго до stop:
echo "
import shutil, glob, os
cands = [d for d in glob.glob('/content/results/*') if os.path.isdir(d)]  # только каталоги!
d = sorted(cands)[-1]
shutil.make_archive('/content/out', 'gztar', d)
print('архив:', os.path.getsize('/content/out.tar.gz'), 'байт из', d)
" | colab --auth=adc exec -s $S --timeout 300
colab --auth=adc download -s $S /content/out.tar.gz /tmp/out.tar.gz
tar -tzf /tmp/out.tar.gz > /dev/null && echo "АРХИВ ЦЕЛ"   # ← ОБЯЗАТЕЛЬНАЯ проверка

# 5. Только теперь:
colab --auth=adc stop -s $S
colab --auth=adc sessions        # должно быть пусто (или только чужие живые прогоны)
```

## Возврат в локальные репозитории (обязательная часть, не опция)

Этот проект возвращает прогоны семинаров ОДНИМ инструментом — руками файлы не носить:

1. Каждая тетрадка последней ячейкой пакует свой прогон: `<name>.json` (метрики + runtime)
   плюс `run_log.txt` (все print сессии) и отдаёт `data:`-ссылку на скачивание.
2. `python3 scripts/import_runs.py --gate` забирает архивы из `~/Downloads`, раскладывает
   каждый дамп ПО ЕГО СОБСТВЕННОМУ `runtime.gpu` (ускоритель → `seminars/runs-t4/`,
   CPU → `seminars/runs/`, чтобы прогон на T4 не затёр базу, с которой его же сверяют),
   складывает логи в `seminars/runs/logs/` и сразу прогоняет G29.
3. Проверить: `python3 _research/check_notebooks.py` — числа прозы обязаны приходить из
   этого дампа или из `data/`. Дамп руками НЕ править: разошлось — перепрогнать тетрадку.
4. Солёные копии для прогона строит `python3 scripts/sync_solved.py` в gitignored
   `tmp/colab-t4/` — решения ГРАФТЯТСЯ из предыдущих копий, не набираются заново.
5. scratchpad — НЕ хранилище: всё ценное немедленно в репозитории.

**Ядро Colab переживает смену тетрадки.** Сборщик дампа идёт по `globals()`, поэтому без
`restart-kernel` между тетрадками в архив попадают переменные предыдущего семинара — G29
ловит это проверкой [K] («в дампе величины, которых нет в тексте тетрадки»). Перезапускать
ядро перед каждой тетрадкой, а не «когда что-то пойдёт не так».

## Оплаченные грабли (полный список — RUNBOOK §11; не переоткрывать)

1. Флаг `--auth=adc` ставится ДО подкоманды; без него сборка лезет в oauth2 и виснет.
2. **Каждый exec/run начинает с `cd /content`** — chdir из прошлого exec не переживает;
   распаковывай репозиторий прямо в /content, чтобы код видел `src/...` от корня.
3. Дефолтный `--timeout` = 30 с/ячейку.
4. **`download` возвращает код 0 даже при провале** — проверка целостности локального
   файла перед stop обязательна; иначе результаты умирают вместе с VM.
   Аварийный канал: ячейка артефактов ноутбуков проекта встраивает zip base64-ом в stdout.
5. Ноутбуки проекта после инфраструктурной ячейки уводят print в Tee → клиент CLI
   stdout НЕ видит; вся печать — в `run_log.txt` внутри каталога результатов; приёмка по нему.
6. Незнакомое значение `--gpu` молча падает в A100. Пиши точно: T4|L4|G4|A100|H100.
7. Параллельные независимые прогоны — разные `-s имена`; при конфликте state-файла
   используй глобальный `--config /tmp/<уникальный>.json`.

## Мини-шаблон для одноразового скрипта (без сессии)

```bash
colab --auth=adc run script.py          # new+exec+stop одной командой, сам чистится
colab --auth=adc run script.py > out.txt  # stdout скрипта отделён от [colab]-шума
```
Для скриптов, пишущих файлы, одноразовый режим НЕ годится (VM умирает) — используй цикл выше.
