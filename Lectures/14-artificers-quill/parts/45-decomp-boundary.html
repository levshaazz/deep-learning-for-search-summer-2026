“Always decompose — more hops, more coverage.”

the boundary · depth has a bill
Misconception

Splitting every query into sub-questions cannot hurt — each hop only adds evidence, so more hops means better answers.

✓ Correction
  • ·Error propagates: \(P_{\text{compose}} = p^{\,n}\) — at \(p=0.90\), three hops already drops to 0.73.
  • ·Latency & cost: one plan call, then one retrieval per sub-question — possibly recursive. Depth multiplies both.
  • ·Single-fact queries: if one chunk already answers it, decomposing only adds hops to fail on.

Decompose when the query is genuinely compound. For a single-fact lookup, the raw query is already the right shape — every extra hop is pure risk and latency.

Boundary/misconception: decomposition is not free. Error propagation (p^n; 0.9^3 = 0.73) and latency both grow with depth — cost is 1 plan call + one retrieval per sub-question, possibly recursive.
