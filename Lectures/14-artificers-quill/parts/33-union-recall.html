Объединение поднимает полноту — но теряет ранжированиеThe union lifts recall — but loses the ranking

покрытие легко; единый упорядоченный список — вот трудная частьcoverage is easy; a single ordered list is the hard part
  • 1Ищи по каждому парафразу отдельно. Каждый возвращает свой ранжированный список попаданий.Retrieve each paraphrase separately. Each returns its own ranked list of hits.
  • 2Возьми объединение. Пассаж, упущенный одной формулировкой, ловится другой — покрытие (полнота) растёт.Take the union. A passage missed by one phrasing is caught by another — coverage (recall) goes up.
  • 3А теперь какой порядок? Наивное объединение выбрасывает каждый ранг по запросу — у тебя мешок попаданий, а не ранжирование.Now what order? A naive union throws away every per-query rank — you have a bag of hits, not a ranking.

Разрыв: конкатенация N списков возвращает полноту, но разрушает единственное, что читает пользователь — единый разумный порядок. Нужно правило слияния, что сливает ранги, а не отбрасывает их.The gap: concatenating N lists recovers recall but destroys the one thing the user reads — a single, sensible order. We need a fusion rule that merges ranks, not one that discards them.

Retrieve each paraphrase, union the hits: recall climbs because different phrasings catch different passages. But a naive union has no coherent ordering — every per-query rank is lost. That missing merge rule is exactly the job RRF does next.
