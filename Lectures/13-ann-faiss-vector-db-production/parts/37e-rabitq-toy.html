Код — это просто знакиThe code is just the signs

\(D = 8\), один байт на вектор\(D = 8\), one byte per vector
$$ o = (0{,}3497,\ -0{,}1354,\ 0{,}6204,\ -0{,}4512,\ 0{,}2030,\ -0{,}2482,\ 0{,}4061,\ -0{,}0564) \;\Rightarrow\; \texttt{10101010} $$
\(\pm\)
Шаг первый: посмотри на знаки
плюс даёт бит 1, минус — бит 0; больше ничего считать не нужно Step one: read the signs
plus gives bit 1, minus gives bit 0; nothing else to compute
\(0{,}3536\)
Шаг второй: разверни код обратно
каждый бит — координата \(\pm 1/\sqrt{8}\); это и есть выбранная вершина Step two: unfold the code
each bit is a coordinate \(\pm 1/\sqrt{8}\); that is the chosen vertex
\(0{,}8734\)
Шаг третий: одно скалярное произведение
\(\langle \bar{o}, o \rangle\) — насколько вершина совпала с вектором Step three: one inner product
\(\langle \bar{o}, o \rangle\) — how well the vertex matched the vector

Восемь измерений уместились в один байт, и обратите внимание, чего в этой процедуре нет: обучения, поиска ближайшего центроида по таблице, самой таблицы. Есть знаки и одно произведение. Именно поэтому построение индекса упирается в скорость чтения векторов, а не в k-средних, — и именно поэтому граница ошибки выводится из размерности, а не измеряется на удачном корпусе. Eight dimensions fit into one byte, and notice what this procedure does not contain: training, a table lookup for the nearest centroid, the table itself. There are signs and one product. That is why index construction is bounded by how fast you can read vectors rather than by k-means — and why the error bound follows from the dimension instead of being measured on a lucky corpus.

Игрушечный разбор к слайду 37b, все числа из data/l9-bench.json → rabitq.toy (считает gen_l9.py на D=8): нормированный вектор, код 10101010 по знакам координат, вершина ±1/√8 = ±0,3536, скалярное произведение 0,8734, один байт на вектор. Смысл слайда — снять мистику: студент видит, что «квантование» здесь это чтение знаков, а «разворот кода» — подстановка ±1/√D. Отсюда два следствия, которые стоит проговорить: сборка индекса ограничена скоростью чтения векторов (обучать нечего), а граница ошибки берётся из свойств поворота, а не из замера. Настоящая процедура добавляет ещё поворот случайной ортогональной матрицей до взятия знаков — здесь он опущен, чтобы арифметика умещалась в голове.
