Каскад: пользователь читает сверху вниз и уходит в тот момент, когда результат его удовлетворяет. Поэтому одно отличное попадание на ранге 1 делает всё под ним почти бесполезным. ERR — это по сути градуированный MRR — награда за то, что пользователь удовлетворён рано.A cascade: the user reads top-down and quits the moment a result satisfies them. So one great hit at rank 1 makes everything below it almost worthless. ERR is essentially a graded MRR — reward for satisfying the user early.

RBP · пользователь, который упорствуетRBP · the user who persists

Пользователь переходит к следующему рангу с фиксированной вероятностью \(p\) и иначе останавливается — поэтому внимание убывает геометрически вниз по списку. Настрой \(p\), чтобы смоделировать терпеливого (\(p\to1\)) vs нетерпеливого (\(p\to0\)) пользователя; дисконт — это ручка настройки, а не фиксированный log.The user steps to the next rank with a fixed probability \(p\) and stops otherwise — so attention decays geometrically down the list. Tune \(p\) to model a patient (\(p\to1\)) vs impatient (\(p\to0\)) user; the discount is a knob, not a fixed log.

Обе заменяют фиксированный log-дисконт nDCG на явную модель пользователя. Алгебра тебе не нужна; для справки: \(\mathrm{ERR}=\sum_r \tfrac{1}{r}R_r\!\prod_{i \lt r}(1-R_i)\) и \(\mathrm{RBP}=(1-p)\sum_r g_r\,p^{\,r-1}\), с вероятностью остановки \(R_r\propto 2^{\mathrm{rel}_r}-1\).Both swap nDCG's fixed log discount for an explicit user model. You don't need the algebra; for reference: \(\mathrm{ERR}=\sum_r \tfrac{1}{r}R_r\!\prod_{i \lt r}(1-R_i)\) and \(\mathrm{RBP}=(1-p)\sum_r g_r\,p^{\,r-1}\), with stop-prob \(R_r\propto 2^{\mathrm{rel}_r}-1\).

Two metrics worth knowing because they encode an explicit user model, unlike nDCG's fixed log discount. Expected Reciprocal Rank assumes a cascade: the user reads down the list and stops as soon as a document satisfies them, so a great result early makes everything below it nearly irrelevant — it's a graded, cascade-aware cousin of MRR. Rank-Biased Precision assumes a persistent user who continues to the next rank with probability p; tune p to model patient versus impatient users. You don't need the algebra memorised — I've left it as a one-line reference at the foot of the slide — but know they exist and why a user model can beat a fixed discount.
