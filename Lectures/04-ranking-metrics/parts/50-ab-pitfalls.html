A/B testing: guardrails & pitfalls

how A/B tests lie

Guardrail metrics

  • ·CTR up but latency up, or revenue down? Watch guardrails, not just the target.
  • ·CTR can rise from clickbait — pair it with dwell / conversion.
  • ·Randomise by user, not session — repeated sessions from one user are correlated, so a naive per-session \(z\)-test understates variance; cluster / bootstrap by user or the \(p\)-value is overconfident.

Three classic traps

!
Peeking · novelty · seasonality

Peeking: checking \(p\) repeatedly inflates false positives — fix \(n\) up front or use sequential tests. Novelty: users click anything new at first. Seasonality: run full weeks, not Tuesday afternoons.

An A/B test answers "did behaviour change", not "did the ranking get better" — guardrails and a clean design keep the two aligned.

A/B tests are powerful but easy to fool. Guardrail metrics catch a treatment that wins on the target while quietly hurting something else — latency, revenue, long-term retention. CTR especially can be gamed by clickbait, so always pair it with a satisfaction signal like dwell time or conversion. Three procedural traps: peeking at the p-value repeatedly is the online cousin of multiple comparisons and inflates false positives — commit to a sample size or use a sequential test; novelty effects make anything new look good for a few days; and seasonality means you must run full weekly cycles. Design first, then run.
