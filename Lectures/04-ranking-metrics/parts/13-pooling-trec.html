Pooling & the Cranfield / TREC paradigm

how test collections are built
Method
Poolingdepth-\(k\) pool

Run many systems on each query; take the top \(k\) from each; union them into a pool; have assessors judge only the pool.

The Cranfield paradigm (1960s) established reusable test collections (judged near-exhaustively); pooling arrived in the 1970s as a sampling technique and TREC (1992–) industrialised it: a reusable test collection = queries + pooled qrels. A document outside every system's top-\(k\) is assumed non-relevant — usually safe, because relevant docs tend to surface near the top of some system.

Cranfield in the 1960s established the recipe that still rules: fixed queries, fixed documents, fixed relevance judgments, so any system can be scored offline and compared — Cranfield itself judged near-exhaustively. The trick that makes large collections affordable is pooling, introduced as a sampling technique in the 1970s: instead of judging all documents, you pool the top-k of every participating system and judge only that union. TREC industrialised it from 1992. The bet is that any genuinely relevant document is found by at least one decent system and lands in the pool. Voorhees showed pooled collections are robust enough to reuse for years.
