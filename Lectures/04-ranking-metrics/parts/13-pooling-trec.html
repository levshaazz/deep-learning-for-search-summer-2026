Pooling & the Cranfield / TREC paradigm

how test collections are built
Method
Poolingdepth-\(k\) pool

Run many systems on each query; take the top \(k\) from each; union them into a pool; have assessors judge only the pool.

The Cranfield paradigm (1960s) → TREC (1992–) standardised this: a reusable test collection = queries + pooled qrels. A document outside every system's top-\(k\) is assumed non-relevant — usually safe, because relevant docs tend to surface near the top of some system.

Cranfield in the 1960s established the recipe that still rules: fixed queries, fixed documents, fixed relevance judgments, so any system can be scored offline and compared. TREC industrialised it from 1992. The trick that makes it affordable is pooling: instead of judging all documents, you pool the top-k of every participating system and judge only that union. The bet is that any genuinely relevant document is found by at least one decent system and lands in the pool. Voorhees showed pooled collections are robust enough to reuse for years.
