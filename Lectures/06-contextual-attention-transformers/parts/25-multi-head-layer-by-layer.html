Один советник видит одну связь. Разбиваем \(d\) на \(h\) подпространств \(d/h\), в каждом — своя голова внимания; выходы конкатенируются и проецируются \(W^O\) обратно в \(d\). У нас \(h=2,\ d_k=4\Rightarrow\) подпространство \(=2\).One councillor sees one relation. We split \(d\) into \(h\) subspaces of size \(d/h\), run an attention head in each; the outputs are concatenated and projected by \(W^O\) back to \(d\). Here \(h=2,\ d_k=4\Rightarrow\) subspace \(=2\).

Multi-head attention as a forward data path. The whole pipeline is on screen from the start — input, split, attend, concatenate, project — with the current stage ringed and the not-yet-reached stages faded, so the projected frame is never empty even at rest. Step zero: the input X, T token vectors each of dimension d, which is four in our example. Step one: we split into h heads — here two — by projecting X with per-head query, key and value matrices, so each head works in a subspace of dimension d over h, which is two. Step two: each head independently runs the full scaled-dot-product attention we just built, so head one might capture one relation and head two a different one. Step three: we concatenate the heads' outputs back up to the full dimension d. Step four: a final learned matrix W output mixes the heads together — and this projection is essential, because concatenation alone just stacks them side by side without letting them talk. Because each head lives in a smaller subspace, the total compute is about that of a single full-size head, so we get several attention patterns nearly for free.
Step 0 — input X: T tokens of dimension d.
Step 1 — split into h=2 heads via per-head Q/K/V projections, each in d/h dims.
Step 2 — each head runs its own scaled-dot-product attention.
Step 3 — concatenate the head outputs back to dimension d.
Step 4 — project by Wᴼ, which mixes the heads → output.
