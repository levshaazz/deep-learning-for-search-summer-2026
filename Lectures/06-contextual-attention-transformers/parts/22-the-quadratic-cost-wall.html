Матрица скоров \(QK^\top\) — это \(n\times n\): время растёт как \(O(n^2 d)\), а сама материализованная матрица скоров стоит \(O(n^2)\) памяти на голову — именно эту память убирает FlashAttention. При \(n=512\) это \({\sim}262\text{k}\) пар; при \(n=8\text{k}\) — \({\sim}67\text{M}\) — это и есть стена длинного контекста. Лечение: sparse (Longformer, BigBird — окно + глобальные токены), linear (Performer/Linear Attention — \(O(n)\)), FlashAttention (точное \(O(n^2)\), но IO-aware — не материализует матрицу).The score matrix \(QK^\top\) is \(n\times n\): time grows as \(O(n^2 d)\), and the materialised score matrix itself costs \(O(n^2)\) memory per head — that memory is the wall FlashAttention removes. At \(n=512\) that is \({\sim}262\text{k}\) pairs; at \(n=8\text{k}\) it is \({\sim}67\text{M}\) — the long-context wall. Fixes: sparse (Longformer, BigBird — windows + global tokens), linear (Performer / Linear Attention — \(O(n)\)), FlashAttention (exact \(O(n^2)\) but IO-aware — never materialises the matrix).

The one real cost of attention, and the reason long context is hard. The score matrix Q K transpose is n by n, where n is the sequence length, so both the compute and, crucially, the memory to hold that matrix grow as n squared times the dimension. At five hundred and twelve tokens that is about a quarter of a million pairs; at eight thousand tokens it is sixty-seven million — the curve in red. The dashed blue line is the linear ideal we wish we had. Three families of fixes exist. Sparse attention — Longformer and BigBird — restricts each token to a local window plus a few global tokens, so the matrix becomes mostly empty. Linear attention — the Performer and friends — rewrites the softmax with a kernel feature map so the cost drops to order n. And FlashAttention keeps the exact quadratic computation but is IO-aware: it never writes the full n by n matrix to slow memory, tiling the work in fast on-chip memory, which gives a large constant-factor speedup and is what most modern stacks actually use. For retrieval we usually cap sequence length, so the wall is felt most in long-document and long-generation settings.
