Как это читать How to read it

Переплата — ровно ω за шов, а не «ещё один проход по документу». Здесь это около 5 % лишних токенов на индексации и ноль на запросе: индекс всё так же хранит по одному вектору на чанк.The overhead is exactly ω per seam, not “one more pass over the document”. Here that is about 5 % extra tokens at index time and zero at query time: the index still stores one vector per chunk.

Хочешь дешевле — уменьшай ω; хочешь длиннее связи через шов — увеличивай. Ручка одна, и она линейна: переплата = (число швов) × ω.Want it cheaper — shrink ω; want longer links across the seam — grow it. One knob, and it is linear: overhead = (number of seams) × ω.

Внимание по-прежнему квадратично по длине окна — но окно фиксировано, поэтому счёт растёт линейно по длине документа. (В §3.1 статьи написано «экспоненциально»; это опечатка — память внимания квадратична.)Attention is still quadratic in the window length — but the window is fixed, so the bill grows linearly with document length. (§3.1 of the paper says “exponentially”; that is a slip — attention memory is quadratic.)

Worked-3, all integers so nothing new needs gating. stride = l_max − ω = 7 680; macro-chunks = ⌈(20 000 − 512)/7 680⌉ = 3; starts 0 / 7 680 / 15 360; coverage 15 360 + 8192 = 23 552 ≥ 20 000; encoded 8192 + 8192 + 4 640 = 21 024; overhead 1 024 = (3−1) × 512 — exactly ω per seam. About 5 % more tokens at index time, nothing at query time. Two corrections worth saying out loud: the cost is ω per seam (not a second full pass), and §3.1's "memory increases exponentially" is wrong — attention memory is quadratic in the window, and since the window is fixed the total is linear in document length.
