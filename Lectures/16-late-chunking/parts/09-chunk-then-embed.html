Что кодирует наивный чанк What the naive chunk encodes
$$ e_i \;=\; \operatorname{pool}\big(\operatorname{Enc}(c_i)\big) $$

где Enc кодирует только токены чанка \(c_i\); окно внимания = один чанк. where Enc encodes only the tokens of chunk \(c_i\); the attention window = one chunk.

Ни один токен \(c_i\) не может attend к токену за его границей — межчанковый контекст разорван до кодирования. No token in \(c_i\) can attend to a token past its boundary — cross-chunk context is severed before encoding.

The naive chunk-then-embed pipeline: split → embed EACH chunk independently → store one vector per chunk. Key defect: e_i = pool(Enc(c_i)) runs the encoder over one chunk in isolation, so the attention window is a single chunk and no token can attend past its boundary. Cross-chunk context is destroyed before the encoder ever runs — that is what late chunking will fix by reordering the two operations.
