«Просто бери чанки побольше» "Just use bigger chunks"

размер чанка — не та ручка chunk size is the wrong knob
Соблазнительное убеждение The tempting belief

«Если маленькие чанки теряют контекст — увеличим чанки, и референт снова окажется внутри». “If small chunks lose context, make the chunks bigger so the referent lands back inside.”

Крупные чанки возвращают коллапс длины — поиск снова портится (нарезка длинного текста давала +24,47%; откат этого выигрыша бьёт по nDCG). И граница всё равно где-то режет зависимость — ты лишь двигаете шов, а не убираете его. Bigger chunks bring back length collapse — retrieval worsens again (chunking a long doc bought +24.47%; undoing it hurts nDCG). And a boundary still cuts some dependency somewhere — you only move the seam, never remove it.

Настоящая ручка — не размер, а когда ты пулишь. Закодируй весь документ сначала, и только потом режь на чанки: внимание уже разрешило «Its» → Berlin до нарезки. Это — late chunking. The real knob is not size but when you pool. Embed the whole document first, then cut into chunks: attention has already resolved "Its" → Berlin before the seam. That is late chunking.

Misconception: "small chunks lose context → just use bigger chunks." Truth: bigger chunks reintroduce length collapse (chunking bought +24.47% rel nDCG, reported; reversing it hurts) AND a boundary still severs some dependency — size only moves the seam. The real fix is not chunk size but WHEN you pool: embed the whole doc first, then cut, so attention resolves the referent pre-boundary. Sets up late chunking.
