Но «drop-in» ≠ «без миграции» But “drop-in” ≠ “no migration”

Формат вектора тот же — но значения другие. Значит корпус придётся переиндексировать целиком: старые и новые векторы в одном индексе несравнимы, и смешанный индекс будет тихо врать.The vector format is the same — but the values are not. So the corpus must be re-indexed in full: old and new vectors in one index are not comparable, and a mixed index lies quietly.

И второе: чанки одного документа теперь обязаны кодироваться вместе. Конвейер, который разбрасывал чанки по воркерам, придётся перестроить — единица работы становится документ, а не чанк.And second: a document’s chunks must now be encoded together. A pipeline that scattered chunks across workers needs rebuilding — the unit of work becomes the document, not the chunk.

The practical takeaway, merged (the two old slides both said "nothing downstream changes"). Left: same d → the same HNSW/IVF index from L9, same query path (one vector per chunk, one dot product), training-free, and the reranker/generator/ANN stay as-is. Right — and this is NEW and the part an engineer actually needs: "drop-in" does not mean "no migration". The values change, so the whole corpus must be re-indexed and a mixed index silently misranks; and because a document's chunks must be encoded together, the unit of work in the indexing pipeline changes from chunk to document, which breaks naive chunk-level parallelism.
