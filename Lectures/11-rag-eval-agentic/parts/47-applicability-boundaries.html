“More loops always help”

applicability boundaries — don't over-agent
What students think

“If a self-correcting loop improves quality, run as many iterations and graders as possible — more reflection must mean more reliability.”

Each loop iteration is another LLM call: more latency, more cost, and another place to fail — a grader can mis-grade, a reflection token can mis-fire, and a loop can wander. For a simple one-hop fact, an agentic loop is pure overhead; Adaptive-RAG exists precisely to not run it. Diagnose the failure first — is it grounding, ranking, coverage, or multi-hop? — then add the one mechanism whose lift matches. And remember Goodhart: more self-grading against a biased judge just teaches the model to game that judge faster. Start simple; earn each loop with a measured, human-anchored win.

The agentic toolkit is a set of scalpels, not a hammer. Match the loop to the question; let the cheapest path that answers it win.
