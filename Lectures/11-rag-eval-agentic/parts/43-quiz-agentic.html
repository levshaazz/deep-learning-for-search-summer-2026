Quick check — why loop at all?

single-shot RAG vs the agentic loop
A user asks: “What did the founder of Acme Corp study?” Single-shot RAG keeps returning facts about Acme Corp but never the founder's education. Why does a ReAct loop succeed where one retrieval fails?
AIt retrieves more chunks at once, so the answer is somewhere in the bigger context.
BIt retrieves the founder's name first, then uses that name in a second retrieval — the bridging fact the first query couldn't express.
CIt uses a bigger model, which already knows the answer without retrieval.
Reveal explanation
B. The answer lives behind an intermediate fact: you can't search for “what the founder studied” until you know who the founder is. Stuffing more chunks (A) doesn't help — the bridging fact isn't phrased like the question, so it never ranks. A bigger model (C) abandons grounding entirely. The loop wins because each Observation updates the next query: lookup the founder → recall@1 still 0 → feed the name back → recall@1 jumps to 1 → finish.
Quiz: multi-hop needs the loop because the answer is behind a bridging fact the first query can't express. Answer B. Drives home that the loop's value is feeding each Observation into the next Action (recall@1 0→1 from the climb), not more chunks (A) or a bigger model (C).
