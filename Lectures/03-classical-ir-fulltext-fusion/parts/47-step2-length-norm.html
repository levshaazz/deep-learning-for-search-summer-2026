Step 2 — length normalization

← fixes the flaw: long docs accrue tf just by being long
$$ \mathcal{F}' = S_1\,\frac{f}{\dfrac{K_1\,\mathrm{len}}{\mathrm{avgdl}} + f} $$
\(\mathrm{len}\)
Doc length
tokens in \(d\)
\(\mathrm{avgdl}\)
Average length

\(\tfrac{\mathrm{len}}{\mathrm{avgdl}}\)
Relative size
\(>1\) penalizes long

Long documents accrue tf just by being long. Scaling \(K_1\) by relative length penalizes them (the sloped line, pivoting at \(\mathrm{avgdl}\)). Full normalization → BM11; drop it (flat line, raw \(K_1\)) → BM15.

The second step addresses a bias in step one: a long document accumulates high term counts simply because it has more words, not because it is more relevant. The fix scales the saturation constant K1 by the document's length relative to the corpus average, so a document twice the average length needs twice the count to earn the same credit. Applying this normalisation fully gives the algorithm called BM11; omitting it entirely, using raw K1, gives BM15. These are the two extremes that BM25 will later interpolate between.
