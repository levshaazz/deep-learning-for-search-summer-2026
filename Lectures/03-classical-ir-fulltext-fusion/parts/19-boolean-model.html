The boolean model & query optimization

AND / OR / NOT · rarest term first

Postings: cat → [D1, D2, D3], dog → [D1, D2], mouse → [D2, D3].

01
AND = intersection
cat AND dog = \([D1,D2,D3]\cap[D1,D2] = [D1, D2]\). Non-empty, unlike space AND team earlier.
[D1, D2]
02
OR = union
dog OR mouse = \([D1,D2]\cup[D2,D3] = [D1, D2, D3]\). Broadens recall.
[D1, D2, D3]
03
NOT = difference
cat AND NOT mouse = \([D1,D2,D3]\setminus[D2,D3] = [D1]\).
[D1]

Optimization
For a multi-term AND, intersect the rarest term first (smallest \(df\)): the running result can only shrink, so later merges are cheap.
rarest first
4/4
The three boolean operators map onto set operations on postings: AND is intersection, OR is union, NOT is difference. Unlike the disjoint space/team example, cat AND dog returns D1 and D2 — boolean works fine when terms co-occur. The key optimisation for a conjunctive query is ordering: start from the rarest term (smallest document frequency) because the intersection can only shrink, so every subsequent merge runs against a tiny list. Query planners in real engines do exactly this.
