The move

precompute once, don't scan per query
Key idea
Index, don't loopoffline build · online lookup

Pay an offline cost once to build a data structure, so that each online query is a few cheap lookups instead of a full \(O(N)\) scan.

The structure is the inverted index: for every term, the list of documents that contain it. A query term becomes a dictionary lookup; the candidate set shrinks from a billion to a few thousand before any scoring happens.

The conceptual pivot of Part 1. The corpus is mostly static; queries are endless. So move all the heavy work to build time and make query time trivial. The inverted index is precisely that trade: build it once, consult it forever. After this slide, every later idea — compression, skip pointers, BM25 scoring — is an optimisation on top of this structure.
