Словарь против вхождений; анатомия вхожденияDictionary vs postings; anatomy of a posting

словарь термов → файл вхожденийterm dictionary → postings file

Две структурыTwo structures

  • ·Словарь — отсортированное множество термов, каждый со своим Dictionary — the sorted set of terms, each with its \(df\) и указателем в файл вхождений. Маленький; хранится в памяти. and a pointer into the postings file. Small; kept in memory.
  • ·Файл вхождений — сами длинные списки, на диске. Большой; потоково читается и распаковывается по требованию.Postings file — the long lists themselves, on disk. Big; streamed and decompressed on demand.

Одно вхождение несётOne posting carries

i
docID · tf · positions

docID идентифицирует документ; identifies the document; tf — сколько раз встречается терм (нужно для BM25); is how many times the term occurs (BM25 needs it); positions перечисляют, где именно (нужно для фразовых запросов / запросов по близости). list where (phrase / proximity queries need them).

напр. e.g. team → (D6, tf=2, [7,8]) — «team» дважды, на позициях токенов 7 и 8. — "team" twice, at token positions 7 and 8.

Split the index into the small in-memory dictionary and the large on-disk postings. The dictionary maps a term to its document frequency and a file offset; the postings file holds the actual lists. A single posting is more than a docID — it carries the term frequency for scoring and, optionally, the positions for phrase and proximity matching.
