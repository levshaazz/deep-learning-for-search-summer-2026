Dictionary vs postings; anatomy of a posting

term dictionary → postings file

Two structures

  • ·Dictionary — the sorted set of terms, each with its \(df\) and a pointer into the postings file. Small; kept in memory.
  • ·Postings file — the long lists themselves, on disk. Big; streamed and decompressed on demand.

One posting carries

i
docID · tf · positions

docID identifies the document; tf is how many times the term occurs (BM25 needs it); positions list where (phrase / proximity queries need them).

e.g. team → (D6, tf=2, [7,8]) — "team" twice, at token positions 7 and 8.

Split the index into the small in-memory dictionary and the large on-disk postings. The dictionary maps a term to its document frequency and a file offset; the postings file holds the actual lists. A single posting is more than a docID — it carries the term frequency for scoring and, optionally, the positions for phrase and proximity matching. This anatomy drives the next two slides: how we build these lists, and how we compress them.
