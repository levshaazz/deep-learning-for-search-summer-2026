Один запрос параллельно попадает в сотни шардов индекса; задержку задаёт самый медленный шард, поэтому каждый должен уложиться в несколько мс.One query hits hundreds of index shards in parallel; the slowest shard sets the latency, so each must finish in a few ms.

Бюджет — жёсткая стенаThe budget is a hard wall

Этапу поиска достаётся лишь доля от ~100 мс; остальное уходит на переранжирование, генерацию сниппетов и сеть. Поэтому поиск первого этапа должен быть сублинейным по размеру корпуса.A retrieval stage gets only a slice of ~100 ms; the rest goes to re-ranking, snippet generation, and the network. So first-stage retrieval must be sublinear in the corpus size.

Вот почему мы один раз предвычисляем структуру и обращаемся к ней на каждый запрос, вместо того чтобы сканировать документы.This is why we precompute a structure once and consult it per query, instead of scanning documents.

The budget is not arbitrary. It is set by human perception (a sluggish UI loses users), by throughput (cost is paid tens of thousands of times per second), and by fan-out (a query is split across many shards and the slowest one wins). Within that hundred-millisecond wall, first-stage retrieval gets only a slice — so it has to be sublinear in N. That requirement is the whole motivation for the inverted index.
