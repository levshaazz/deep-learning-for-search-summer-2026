обзорoverview
Exact from the compression JSON. Storing four docIDs as 32-bit ints is 16 bytes. Because postings are sorted, we store gaps instead: 3, 5, 4, 18. Every gap is below 128, so variable-byte coding — seven data bits plus a continuation bit per byte — uses one byte each, four bytes total, a four-times reduction. Why bother: postings dominate index size, and a smaller index stays in cache and cuts IO, which is the real bottleneck at query time. Modern engines use fancier codecs (PForDelta, Simple-9, Roaring) but the gap-then-encode idea is the same.
