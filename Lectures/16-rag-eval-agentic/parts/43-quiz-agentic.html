Почему цикл ReAct преуспевает там, где одно извлечение проваливается?A user asks: “What did the founder of Acme Corp study?” Single-shot RAG keeps returning facts about Acme Corp but never the founder's education. Why does a ReAct loop succeed where one retrieval fails?
AОн извлекает больше фрагментов сразу, поэтому ответ где-то в большем контексте.It retrieves more chunks at once, so the answer is somewhere in the bigger context.
BОн сперва извлекает имя основателя, затем использует это имя во втором извлечении — связующий факт, который первый запрос не мог выразить.It retrieves the founder's name first, then uses that name in a second retrieval — the bridging fact the first query couldn't express.
CОн использует модель побольше, которая уже знает ответ без извлечения.It uses a bigger model, which already knows the answer without retrieval.

B. Ответ живёт за промежуточным фактом: нельзя искать «что изучал основатель», пока не знаешь, кто основатель такой. Набивать больше фрагментов (A) не помогает — связующий факт сформулирован не как вопрос, поэтому не ранжируется. Модель побольше (C) вовсе бросает заземление. Цикл побеждает, потому что каждое Наблюдение обновляет следующий запрос: найди основателя → recall@1 всё ещё 0 → верни имя обратно → recall@1 прыгает к 1 → finish.B. The answer lives behind an intermediate fact: you can't search for “what the founder studied” until you know who the founder is. Stuffing more chunks (A) doesn't help — the bridging fact isn't phrased like the question, so it never ranks. A bigger model (C) abandons grounding entirely. The loop wins because each Observation updates the next query: lookup the founder → recall@1 still 0 → feed the name back → recall@1 jumps to 1 → finish.
