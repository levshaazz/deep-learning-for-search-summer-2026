Что люди предполагаютWhat people assume

«Модель одна и та же, значит вектор запроса и вектор пассажа сравнимы. Префикс query: можно и забыть — на пару процентов, не больше.»“It’s the same model, so the query vector and the passage vector are comparable. You can forget the query: prefix — a couple of percent at most.”

Семейство E5 обучено с префиксами. query:  и passage:  — часть входа, а не украшение: с ними модель училась, без них она получает текст, которого не видела. Закодировал корпус как passage:, а запрос отдал голым — и потерял качество тихо: ни исключения, ни строчки в логах, поиск просто стал хуже. Тот же класс ошибки — закодировать корпус одной моделью, а запрос другой.The E5 family was trained with prefixes. query:  and passage:  are part of the input, not decoration: the model learned with them, and without them it receives text it never saw. Encode the corpus as passage: and hand it a bare query — you lose quality silently: no exception, no log line, search simply gets worse. Same class of bug: encoding the corpus with one model and the query with another.

Это и есть симметрия акта 3. В Акте 2 симметрия значила «один лемматизатор в обоих плечах». Здесь она значит одно и то же преобразование в обоих плечах: та же модель, та же версия, тот же префикс, та же нормировка вектора. Не «нормализация» — тождество конвейера. This is Act 3’s symmetry. In Act 2 symmetry meant “one lemmatizer in both arms”. Here it means the same transformation in both arms: same model, same version, same prefix, same vector normalization. Not “normalization” — pipeline identity.

The counterexample that repairs the lecture's own thesis. Act 2 phrased symmetry as "normalize both arms the same way", which does not literally apply to dense retrieval — nothing is normalized there. The correct general form is: apply the same transformation to query and corpus. The E5 family makes that concrete, because it was trained with "query: " and "passage: " prefixes; drop the query prefix and you feed the encoder an input distribution it never saw. The damage is invisible — no error, no exception, no log line, just a quieter ranking. The same failure mode covers encoding the corpus with one model version and the query with another, or normalizing one side's vectors and not the other. Ask the room how they would have caught this: only an end-to-end retrieval metric on held-out Russian queries catches it.
