раскладка → регистр и NFC → ё/е → confusables → опечатки → нормализация layout → case and NFC → ё/е → confusables → typos → normalization
  • ·Классов ошибок больше одного. Кроме раскладки живут пропуски букв («агенство»), соседние клавиши («поимк») и фонетика («Таиланд» через «й»). Карта клавиш лечит только первый класс — остальные требуют исправлялки.There is more than one error class. Beyond the layout live dropped letters (“агенство”), neighbouring keys (“поимк”) and phonetics (“Таиланд” with “й”). The key map cures only the first — the rest need a corrector.
  • ·Главный практический совет. Расстояние Дамерау—Левенштейна считай по леммам, а не по формам. Иначе «котятам» и «котята» окажутся на расстоянии 1, и исправлялка «починит» падеж — то есть подменит запрос пользователя другим.The practical rule. Compute Damerau–Levenshtein distance over lemmas, not surface forms. Otherwise “котятам” and “котята” sit at distance 1 and the corrector “fixes” the case ending — that is, replaces the user’s query with a different one.
  • ·Почему такой порядок. Каждый шаг сужает алфавит для следующего: пока строка на латинице, расстояние по русскому словарю бессмысленно. Исправлялка идёт предпоследней, нормализация — последней, и та же цепочка повторяется в индексном плече.Why this order. Each step narrows the alphabet for the next: while the string is Latin, distances against a Russian dictionary are meaningless. Correction runs second-to-last, normalization last — and the same chain repeats in the index arm.
The bridge from Act 4 to L15's query understanding. Keyboard layout is only one class of query error; dropped letters, neighbouring-key slips and phonetic misspellings all survive the ЙЦУКЕН↔QWERTY map and need a real corrector. The one rule worth memorising: compute Damerau–Levenshtein distance over lemmas, not surface forms — otherwise inflected variants of the same lexeme sit at distance 1 and the corrector silently rewrites the user's case ending into a different query. Pipeline order: layout restoration, then case and NFC, then ё/е, then confusables, then typo correction, then normalization — each step narrows the alphabet the next one works in, and the same chain must run in the index arm.
