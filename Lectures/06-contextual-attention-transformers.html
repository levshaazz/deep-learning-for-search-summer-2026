«bank»: один вектор, два смысла“bank”: one vector, two meanings

полисемия · усреднённая точкаpolysemy · the averaged point

«river bank» и «bank account» делят один статический вектор из L5 — его координаты усредняют оба смысла. Контекста в нём нет.“river bank” and “bank account” share one static L5 vector — its coordinates average both senses. There is no context in it.

State the problem with the canonical example. In the static map of Lecture 5, the word bank has exactly one vector, fixed before we ever see a sentence. But river bank and bank account are different things. The single point is forced to sit somewhere between the two senses, averaging them, which is wrong for both. No amount of training a static embedding fixes this — the limitation is structural, one word, one vector. What is missing is context: the vector should depend on the sentence the word appears in. That is the whole motivation for contextual embeddings, and attention is how we build them.

The wish, stated as a definition. We want to upgrade the embedding from a function of the word alone to a function of the word and its context. Formally, instead of w maps to v sub w, we want the pair of word and context to map to a vector. Then the same surface word bank produces two distinct vectors when its neighbours differ — river pulls it one way, account the other. The question is how a model can let neighbours influence a token's vector, in a way that is learnable and parallel. The answer is the attention mechanism, and we build it next.
Часть 01Part 01

A Vector per Context

Не координата на слово — координата на употребление:Not a coordinate per word — a coordinate per use: одно слово, разные точки в разных предложениях.the same word, different points in different sentences.

The turn. We are moving from a static map to a dynamic one. In the static world each word was a fixed star; in the contextual world a word's position is computed fresh for each sentence. The same token can land in two different places depending on what surrounds it. This single change is what splits the two banks apart, and it is also what makes a sentence vector finally meaningful — because the parts now know about each other. The mechanism that computes those context-aware positions is attention.

Make the contrast concrete, as a side-by-side. A static embedding, like word2vec or GloVe, is a lookup table — you index in with the word string and read out a fixed vector, so bank gets one point for both senses, depending only on the word. A contextual embedding, as in ELMo in early 2018 and then BERT, is the output of a neural network that has read the whole sentence, so river bank and bank account get different vectors — it depends on the word and its context. The price is computation: a lookup is instant, but a contextual vector requires running the sentence through a stack of attention layers. The rest of this lecture builds that stack, one mechanism at a time.
Часть 02Part 02

Let Each Token Attend

Каждый токен — советник:Every token is a councillor: его новый смысл — взвешенная смесь соседей, к которым он прислушался.its new meaning is a weighted blend of the neighbours it heeded.

The attention idea, before any matrices. Picture each token as a councillor at the round table. To update its own meaning, it does not shout — it listens. It asks every other token how relevant they are to it, gets a weight for each, and then forms its new representation as a weighted average of what those tokens contain. A token surrounded by river will heed river; the same token surrounded by account will heed account. That weighted blend is the entire intuition. Next we make it precise with three roles — query, key, value — and a dot product.

The three roles, with the search analogy you already know. Every token produces three vectors. The query is what this token is looking for. The key is what each token advertises about itself. The value is what a token actually contributes if it is attended to. The attention weight between two tokens is the similarity of one's query to the other's key, so a token with a matching key gets a high weight. The output for a token is the weighted sum of all the values, using those weights. It is exactly soft retrieval, but inside one sentence: the query matches keys, and the matching values are blended in. The picture shows one token's query lighting up its most relevant neighbours.

Scaled Dot-Product Attention

Метафора заработана — теперь точные числа:The metaphor is earned — now the exact numbers: \(\mathrm{softmax}(QK^\top/\sqrt{d_k})V\) на «the cat sat».\(\mathrm{softmax}(QK^\top/\sqrt{d_k})V\) on “the cat sat”.

The climb. We now turn the query-key-value metaphor into the one formula that runs every Transformer: attention equals softmax of Q K transpose over root d k, times V. The formula, read left to right. Stack the queries, keys and values as matrices whose rows are tokens. Q K transpose gives a T by T matrix whose entry i j is the dot product of query i with key j — the raw match score. Divide every entry by root d k; with a key dimension of four that divisor is exactly two. Apply softmax along each row, which turns that row of scores into a probability distribution that sums to one — the attention weights. Finally multiply by V, so each output row is the weighted average of the value rows. Three matrix multiplies and a softmax; that is the whole mechanism. Next we run it on real numbers.

The one real cost of attention, and the reason long context is hard. The dashed blue line is the linear ideal we wish we had. Three families of fixes exist. Sparse attention — Longformer and BigBird — restricts each token to a local window plus a few global tokens, so the matrix becomes mostly empty. Linear attention — the Performer and friends — rewrites the softmax with a kernel feature map so the cost drops to order n. And FlashAttention keeps the exact quadratic computation but is IO-aware: it never writes the full n by n matrix to slow memory, tiling the work in fast on-chip memory, which gives a large constant-factor speedup and is what most modern stacks actually use. Attention is Order-Blind

«dog bites man» = «man bites dog»“dog bites man” = “man bites dog” — без позиции внимание видит мешок токенов. Вернём порядок.— without position, attention sees a bag of tokens. Give order back.

The order problem, and it is a real one. Look back at the attention formula: it is a sum over tokens, and a sum does not care about order. Permute the input tokens and you simply permute the output rows — the actual computation is identical. That means dog bites man and man bites dog would, to a pure attention layer, be the same bag of tokens with the same representations. For language that is fatal; word order carries meaning. So before the first attention layer we add a positional encoding to every token, a signal that says where in the sequence this token sits. The sinusoidal scheme is next.

Make the invariance explicit, because it surprises people. Attention computes, for each token, a weighted sum over all tokens; permute the rows of the input and the set of pairwise scores is unchanged, so the outputs simply permute along. Formally the layer is equivariant to permutation and carries no inherent notion of first, second, third. Recurrent networks got order for free because they processed tokens one at a time; a Transformer processes them all at once, in parallel, which is exactly why it is fast but also why it is order-blind. The remedy is to add a positional encoding to each input token before the stack — position is injected, not emergent.

A quick trade-off so you know the landscape. The sinusoidal encoding has zero parameters because it is a closed-form function, and it can in principle handle positions longer than any seen in training, since you just evaluate the sinusoids further out. A learned positional encoding instead stores a lookup table of one vector per position up to some maximum length — flexible, but it cannot extrapolate past that maximum and adds parameters. The original Transformer paper reported the two performing about equally and chose sinusoids for the extrapolation property. In practice BERT and GPT-2 used learned tables; and modern models often use relative schemes like RoPE or ALiBi, which encode the offset between tokens rather than absolute position. The principle, though, is constant: position must be injected.

LayerNorm precisely, because the over-what matters. For each token independently, compute the mean and variance across that token's d feature values, subtract the mean, divide by the standard deviation plus a tiny epsilon for numerical safety, then apply a learned per-feature scale gamma and shift beta. The crucial contrast with batch normalisation is the axis: BatchNorm normalises each feature across the examples in a batch, whereas LayerNorm normalises each example across its features. That makes LayerNorm independent of batch size and of the other sequences in the batch — exactly what you want for variable-length text where batch statistics would be unstable. The second turn of the lecture. We have a contextual encoder, but its raw vectors are not organised for retrieval. Normalising every vector to unit length removes the magnitude, and the dot product becomes pure cosine — the angle alone. The trap, made precise, with the L2 callback. Anisotropy means the embedding cloud is not spread evenly — it occupies a thin cone, so any two vectors, even for unrelated sentences, share a small angle and therefore a deceptively high cosine, around zero point six or more on random pairs. Ethayarajh in 2019 measured exactly this in BERT, ELMo and GPT-2. Cosine cannot rank well when everything looks similar, and this is the same curse-of-dimensionality pathology the Wraith embodied back in Lecture 2 — distances concentrate, contrast vanishes. The cure is twofold and is precisely what we just built: contrastive training actively pushes negatives apart, spreading the cone, and normalisation onto the sphere restores a usable geometry. A nod to the Wraith, whose full reckoning waits for Lecture 9.

The first cross-domain transfer: vision. The Vision Transformer, from Dosovitskiy and colleagues in 2021, does something almost embarrassingly simple. Take an image, cut it into a grid of small patches — sixteen by sixteen pixels each — and flatten and linearly project each patch into a vector. Now you have a sequence of patch tokens, two hundred or so for a standard image, and you feed them through exactly the same encoder block we built today: positional encoding, multi-head attention, Add and Norm, feed-forward. A CLS token pools the whole image into a single vector, just like BERT pools a sentence. No convolutions anywhere. Given enough training data this beats the convolutional networks that dominated vision for a decade. The lesson that matters for us is the universality: the architecture did not change at all, only the tokenizer that turns the raw input into a sequence. This is the direct ancestor of the multimodal retrieval models we will meet in Lecture 12.

The second transfer, and it reuses today's loss verbatim. CLIP, from Radford and colleagues in 2021, trains two encoders at once — an image encoder, often a Vision Transformer, and a text encoder, a Transformer — and forces them to project into one shared space. How does it align them? With exactly the InfoNCE loss we derived two sections ago. Take a batch of B image-caption pairs, compute the B by B matrix of cosine similarities between every image and every caption, and apply InfoNCE so that each image's true caption is the positive and the other B minus one captions are in-batch negatives — and symmetrically for each caption. That is the entire training signal. The payoff is striking: zero-shot image classification by comparing an image to text prompts, and text-to-image retrieval, both falling straight out of cosine nearness in the shared space. The temperature tau, the cosine, the in-batch-negatives trick — every piece is what we built today, just with one tower fed pixels instead of words.

The closing unification. Step back and the Transformer stops looking like a language model and starts looking like something more general. Treat each token as a node in a graph and each attention weight as the strength of an edge; then a single attention layer is exactly one round of message-passing on that graph, where every node collects a weighted sum of messages from its neighbours. The graph just happens to be complete — every token attends to every token — and positional encoding substitutes for the explicit edges that a real graph would carry. Veličković and colleagues' Graph Attention Network from 2018 is the same idea made explicit on arbitrary graphs. And once you see attention as message-passing on tokenised inputs, the whole zoo lines up: wav2vec tokenises audio into signal windows, ViT and CLIP tokenise images, protein language models like ESM treat amino acids as words and replace BLAST search with embedding search, DNABERT does the same for the genome, and graph attention networks operate on molecules and social graphs. The recipe is always the same three moves: tokenise the modality, train contrastively, search by cosine. Everything is a sequence of tokens in a learned space — which brings us all the way home, to the creature this whole journey was about.
