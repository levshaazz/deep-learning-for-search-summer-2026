MRR и MAP живут на наборе запросовMRR and MAP live on a query set

шаг (←/→): два запроса → обратный ранг каждого → средняя точность каждого → MRR → MAPstep (←/→): two queries → each one’s reciprocal rank → each one’s average precision → MRR → MAP

Один запрос умеет врать — поэтому усредняем. Прощёлкай оба запроса сам: сперва каждый получает свой обратный ранг и свою среднюю точность, и только потом из них собираются MRR и MAP. Обрати внимание: итог не совпадает ни с одним запросом по отдельности — именно поэтому метрику всегда сообщают по набору, а не по любимому примеру.A single query can lie — so we average. Click through both queries yourself: first each one earns its own reciprocal rank and its own average precision, and only then do MRR and MAP get assembled out of them. Notice that the final number matches neither query on its own — which is exactly why a metric is always reported over a set, never over a favourite example.

Act 3’s climb, placed after the MAP definition and before the worked AP/MAP slide. Both queries and every intermediate value come from data/l4-multiquery.json — the same two-query setup the MRR-walked slide used, so students recognise the material. Steps: (0) the two hit patterns; (1) reciprocal ranks — only the FIRST hit matters, contrast the two queries; (2) average precisions — every hit matters now; (3) averaging into MRR; (4) averaging into MAP — DWELL on “the final number is neither query”. Students stumble on RR vs AP on the same ranking (one number from one position vs one number from all hit positions); the side-by-side at steps 1–2 is built to separate them. The worked slide that follows then serves as the on-paper replay.
