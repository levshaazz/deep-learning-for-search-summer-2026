ЗаблуждениеMisconception

Разбиение каждого запроса на подвопросы не может навредить — каждый переход лишь добавляет свидетельства, значит больше переходов — лучше ответы.Splitting every query into sub-questions cannot hurt — each hop only adds evidence, so more hops means better answers.

Декомпозируй, когда запрос действительно составной. Для однофактового поиска сырой запрос уже правильной формы — каждый лишний переход — чистый риск и задержка.Decompose when the query is genuinely compound. For a single-fact lookup, the raw query is already the right shape — every extra hop is pure risk and latency.

Boundary/misconception: decomposition is not free. Error propagation (p^n; 0.9^3 = 0.73) and latency both grow with depth — cost is 1 plan call + one retrieval per sub-question, possibly recursive. For single-fact queries, one chunk already answers, so decomposing only adds hops that can fail. Decompose only when the query is genuinely compound.
