ColBERT

эмбеддинг на токен; документы — заранее; взаимодействие на запросеan embedding per token; docs precomputed; interact at query time

Каждый токен запроса и документа получает свой 128-мерный вектор (\(E_q \in \mathbb{R}^{|q|\times128}\)). Это один общий BERT-энкодер в двух режимах: префикс \([Q]\) (с дополнением [MASK]) против \([D]\) — не две разные модели. Векторы документа считаются офлайн и кэшируются — взаимодействие происходит дёшево, на запросе (отсылка L2: всё — последовательность токенов).Each query and document token gets its own 128-dim vector (\(E_q \in \mathbb{R}^{|q|\times128}\)). It is one shared BERT encoder run in two modes: the \([Q]\) prefix (with [MASK] augmentation) vs \([D]\) — not two separate models. The document vectors are computed offline and cached — interaction happens cheaply, at query time (callback L2: everything is a sequence of tokens).

Оператор MaxSimThe MaxSim operator

для каждого токена запроса — максимум по токенам документа, затем суммаper query token, the max over doc tokens, then the sum
$$ S_{q,d} \;=\; \sum_{i \in q} \max_{j \in d} \; E_{q_i} \cdot E_{d_j} $$

где Sq,d = оценка релевантности пары запрос–документ, i = токен запроса, j = токен документа, Eqi = эмбеддинг токена запроса, Edj = эмбеддинг токена документа (оба L2-нормированы, поэтому скалярное произведение — это косинус).where Sq,d = the query–document relevance score, i = a query token, j = a document token, Eqi = the query token's embedding, Edj = the document token's embedding (both L2-normalized, so the dot is a cosine).

Векторы L2-нормированы, поэтому скалярное произведение — это косинус. Каждый токен запроса «салютует» одному токену документа, с которым совпадает лучше всего (\(\max_j\)); оценка — сумма этих лучших салютов. Не средний по всем парам — именно максимум, затем сумма (отсылка L2: косинус как линейка). MaxSim — несимметричная оценка, а не вероятность. Для эффективного поиска по нему нужен многовекторный каскад: одно скалярное произведение двух суммарных векторов не воспроизводит сумму максимумов. ANN бывает и неметрическим — здесь важна форма взаимодействия многих векторов.Vectors are L2-normalized, so the dot product is a cosine. Each query token "salutes" the one document token it matches best (\(\max_j\)); the score is the sum of those best salutes. Not an average over all pairs — a max, then a sum (callback L2: cosine as a ruler). MaxSim is an asymmetric score, not a probability. Efficient retrieval needs a multi-vector cascade: a single dot product between two pooled vectors does not reproduce the max-then-sum operation. ANN can be non-metric too; the issue here is the form of multi-vector interaction.
