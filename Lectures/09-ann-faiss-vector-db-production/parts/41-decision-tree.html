How to pick one

three axes: graph · partition · compression

Each lane answers a different question. Walk the tree top-down.

01
Does it fit in RAM uncompressed?
Yes → no PQ needed. No → you need compression (PQ): IVF-PQ or HNSW-PQ. Memory is the first hard wall at billion scale.

02
Is lowest latency the priority?
Yes → a graph (HNSW): \(O(\log N)\) walk, recall tuned live. Pair with PQ (HNSW-PQ) if it also must be compressed.
graph
03
Is cheap training / easy updates the priority?
Yes → a partition (IVF): just \(k\)-means, cheap inserts, nprobe retunable. Add PQ (IVF-PQ) for RAM — the billion-scale workhorse.

Decision-tree walkthrough on three axes. (1) Fits RAM? No → PQ. (2) Lowest latency? → graph (HNSW), HNSW-PQ if also compressed. (3) Cheap training / easy updates? → partition (IVF), IVF-PQ for RAM. (4) Tiny / baseline → flat (exact ground truth). Maps the three primitives to the five indexes of the matrix; complexities reference l9-compare.
