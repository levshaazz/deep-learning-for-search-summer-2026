Почему прогулка — \(O(\log N)\), а не \(O(N)\)Why the walk is \(O(\log N)\), not \(O(N)\)

слоистый граф как утверждение с доказательствомthe layered graph, as a proposition with a proof
Утверждение · логарифмический поискProposition · logarithmic search
На HNSW-графе над \(N\) точками, где каждый слой хранит долю \(1/m\) от слоя ниже (\(\approx \log_m N\) слоёв), а жадный поиск выполняет \(O(1)\) ожидаемой работы на слой, ожидаемое число вычислений расстояния до ближайшего соседа — \(O(\log N)\), что намного дешевле полного перебора \(O(N\cdot d)\).On an HNSW graph over \(N\) points where each layer keeps a \(1/m\) fraction of the one below (\(\approx \log_m N\) layers) and greedy search does \(O(1)\) expected work per layer, the expected distance evaluations to reach the nearest neighbour is \(O(\log N)\) — far cheaper than the \(O(N\cdot d)\) brute-force scan.
Набросок доказательстваProof sketch
Оставляй каждую точку на следующем слое вверх с вероятностью \(1/m\). Ожидаемое число слоёв — \(\mathbb{E}[\text{layers}]\approx\log_m N\). Наверху жадный поиск достигает локально-ближайшего хаба за \(O(1)\) переходов. Одним слоем ниже граф плотнее в \(m\) раз, но связность малого мира снова удерживает ожидаемое число переходов на \(O(1)\). Суммируя \(O(1)\) по \(\log_m N\) слоям, получаем \(\sum_{\ell}O(1)=O(\log_m N)=O(\log N)\). Параметр \(M\) задаёт \(m\); больше \(M\) — плотнее слои, выше полнота, больше памяти. \(\blacksquare\)Keep each point on the next layer up with probability \(1/m\). The expected layer count is \(\mathbb{E}[\text{layers}]\approx\log_m N\). At the top, greedy search reaches the locally-nearest hub in \(O(1)\) hops. One layer down, the graph is denser by a factor \(m\), but small-world connectivity keeps the expected hops \(O(1)\) again. Summing \(O(1)\) over \(\log_m N\) layers gives \(\sum_{\ell}O(1)=O(\log_m N)=O(\log N)\). The parameter \(M\) sets \(m\); larger \(M\), denser layers, higher recall, more memory. \(\blacksquare\)
Оговорка: это эмпирическая / ожидаемая сложность, а не гарантия для худшего случая. Шаг «\(O(1)\) переходов на слой» предполагает, что граф остаётся навигируемым — недоказанное для произвольных данных; враждебные или кластеризованные входы могут выродить жадный поиск в линейный.Caveat: this is the empirical / expected complexity, not a worst-case guarantee. The \(O(1)\)-hops-per-layer step assumes the graph stays navigable, unproven for general data — adversarial or clustered inputs can degrade greedy search toward linear.

Malkov & Yashunin (arXiv 2016; IEEE TPAMI 2020).

O(log N) theorem thm-card (statement + proof). Layers keep a 1/m fraction each → ≈log_m N layers; O(1) expected hops per layer (small-world property) → O(1) summed over log_m N layers = O(log N).
