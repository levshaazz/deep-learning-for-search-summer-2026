Same vectors, different top-1

why the metric is a modeling choice, not a detail

Query \(q=[2,2,0,0]\) against \(d_1=[2,1,0,0]\), \(d_2=[3,3,0,0]\), \(d_3=[7,4,0,0]\). Watch each metric crown a different winner.

01
L2 → \(d_1\)
\(\lVert q-d_1\rVert=1.0\), \(\lVert q-d_2\rVert=1.4142\), \(\lVert q-d_3\rVert=5.3852\). The smallest displacement wins — \(d_1\), the nearest point, even though it is not perfectly aligned.
d1 · 1.0
02
cosine → \(d_2\)
\(\cos(q,d_1)=0.9487\), \(\cos(q,d_2)=\mathbf{1.0}\), \(\cos(q,d_3)=0.9648\). \(d_2=[3,3,0,0]\) points exactly along \(q\) — perfect alignment scores 1.0 regardless of length. cosine crowns \(d_2\).
d2 · 1.0
03
inner product → \(d_3\)
\(q\cdot d_1=6\), \(q\cdot d_2=12\), \(q\cdot d_3=\mathbf{22}\). The raw dot rewards magnitude: long \(d_3=[7,4,0,0]\) wins on sheer size, despite worse alignment than \(d_2\).
d3 · 22
→
cosine = inner product on normalized vectors
FAISS ships only METRIC_L2 and METRIC_INNER_PRODUCT. Cosine is the identity \(\cos(a,b)=\frac{a\cdot b}{\lVert a\rVert\lVert b\rVert}\) — so \(L_2\)-normalize once, then use inner product. Choose the metric your task needs before you build the index.

Ranking-disagreement walkthrough. Numbers verbatim from data/l9-metrics.json ranking block: L2 [1.0, 1.4142, 5.3852] → d1; cosine [0.9487, 1.0, 0.9648] → d2; dot [6, 12, 22] → d3. The lesson: the same three candidates produce three different top-1 under the three metrics. Production tie-in: FAISS only has METRIC_L2 / METRIC_INNER_PRODUCT; cosine = normalize then inner product. The metric is chosen before index construction because the index is built around it.
