где nprobe = число ячеек, просматриваемых на один запрос, N = общее число векторов в базе, nlist = число ячеек Вороного (центроидов), d = размерность вектора.where nprobe = the number of cells scanned per query, N = the total number of database vectors, nlist = the number of Voronoi cells (centroids), d = the vector dimensionality.

Запусти \(k\)-means, чтобы выбрать nlist центроидов, разрезая пространство на ячейки Вороного. Грубый квантователь отображает любой вектор в ближайший центроид; каждый вектор базы заносится под свою ячейку — один раз, офлайн. (Та же идея инвертированного списка, что и в индексе постингов из L3 — но «термом» здесь выступает центроид.)Run \(k\)-means to pick nlist centroids, carving the space into Voronoi cells. The coarse quantizer maps any vector to its nearest centroid; every database vector is filed under its cell — once, offline. (Same inverted-list idea as the L3 postings index — but the "term" is a centroid.)

Во время запроса найди nprobe ячеек, чьи центроиды ближе всего к запросу, и просканируй только их — не все \(N\) векторов. Стоимость поиска \(\approx O(\textrm{nprobe}\cdot \tfrac{N}{\textrm{nlist}}\cdot d)\).At query time, find the nprobe cells whose centroids are nearest the query and scan only those — not all \(N\) vectors. Search cost \(\approx O(\textrm{nprobe}\cdot \tfrac{N}{\textrm{nlist}}\cdot d)\).

Больше ячеек (крупнее nlist) → меньше векторов на ячейку → быстрее, но истинный сосед вероятнее окажется в ячейке, которую ты не зондировал. nprobe меняет полноту на скорость.More cells (larger nlist) → fewer vectors per cell → faster, but a true neighbour is likelier to fall in a cell you didn't probe. nprobe trades recall for speed.
