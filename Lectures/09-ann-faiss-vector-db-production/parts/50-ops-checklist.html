  • Обслуживай под SLA — бюджетируй каждый переход; предупреждай по \(p_{99}\), а не \(p_{50}\) (здесь \(p_{99}=180\) мс против потолка \(200\) мс).Serve under the SLA — budget every hop; alert on \(p_{99}\), not \(p_{50}\) (here \(p_{99}=180\)ms vs the \(200\)ms ceiling).
  • Мониторь полноту и задержку — полнота молча деградирует по мере дрейфа данных; плоский дашборд — не значит здоровый.Monitor recall and latency — recall silently decays as data drifts; a flat dashboard is not a healthy one.
  • Перестраивай индекс по мере добавления, изменения, удаления документов — устаревшие графы и списки теряют соседей.Rebuild the index as documents are added, changed, deleted — stale graphs and lists lose neighbours.
  • Переобучай квантователи при дрейфе — центроиды IVF и кодовые книги PQ обучались на старых данных; обнови их.Retrain quantizers on drift — IVF centroids and PQ codebooks were trained on old data; refresh them.
  • Кэшируй горячий хвост — повторы возвращаются за \(\approx 5\) мс; инвалидация кэша следует за перестройками индекса.Cache the hot tail — repeats return in \(\approx 5\)ms; cache invalidation tracks index rebuilds.
  • Бюджетируй RAM — сжатый индекс всё равно должен поместиться; рассчитывай его от \(N\times\) байт/вектор.Budget the RAM — the compressed index still has to fit; size it against \(N\times\) bytes/vector.
  • Фильтр + ANN вместе — фильтры по метаданным и окна свежести взаимодействуют с ячейками/графом; тестируй их как один путь.Filter + ANN together — metadata filters and freshness windows interact with the cells/graph; test them as one path.
  • Держи flat как базовый вариант — точный эталон, с которым ты всегда сверяешь полноту.Keep a flat baseline — the exact ground truth you measure recall against, forever.
