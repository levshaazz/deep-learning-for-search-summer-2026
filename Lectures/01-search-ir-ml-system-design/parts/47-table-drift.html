Drift & the data pitfalls

Match the fix to the failure
Pitfall What changes How to catch it
Covariate shift \(P(x)\) (holiday traffic) monitor feature dist · KL / PSI
Concept drift \(P(y\mid x)\) ("corona" pre/post-2020) error vs fresh labels
Data leakage future leaks into train split by time, not at random
Label delay conversions arrive late "no conversion" ≠ "not yet"
Simpson's paradox traffic mix shifts always cut by segment

Applying a covariate-shift fix to concept drift solves nothing — the diagnosis determines the cure. Cold start (new user/query/doc, no history) needs content features, popularity priors, and exploration.

The discipline is matching diagnosis to cure. Covariate shift (\(P(x)\) moves, \(P(y\mid x)\) fixed) is caught by watching feature distributions — KL divergence or PSI. Concept drift (\(P(y\mid x)\) itself moves) is invisible in feature distributions; you only see it as rising error against fresh labels. Leakage is the offline-metric inflator — random splits on temporal data leak the future. Simpson's paradox: if the aggregate moves but no cohort moves the same way, suspect a traffic-mix shift and never trust the aggregate alone.
