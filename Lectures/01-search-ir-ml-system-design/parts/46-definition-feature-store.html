The #1 silent killer — and its architectural fix

Definition
Definition
Training–serving skew + the feature store that kills it

Skew = the features at serving time differ from those at training time — different code paths, data that changed in between, or a feedback loop. The model trained on one distribution, serves on another, and degrades silently.

Fix — a feature store: one source of feature values for both training and serving, guaranteeing parity. (Google Rules #29 "train like you serve", #32 "reuse code between training and serving".)

Train/serve skew is the most common silent production failure. The root cause is two code paths computing "the same" feature slightly differently, or a feature that drifts between when you trained and when you serve. The architectural fix is the feature store — compute each feature once, write it where both training and serving read it. This is exactly the bridge node in the production blueprint two slides from now.
