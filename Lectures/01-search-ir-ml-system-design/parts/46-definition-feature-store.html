Перекос = признаки во время выдачи отличаются от признаков во время обучения — разные пути в коде, изменившиеся между этим данные или петля обратной связи. Модель обучилась на одном распределении, обслуживает на другом и деградирует незаметно.Skew = the features at serving time differ from those at training time — different code paths, data that changed in between, or a feedback loop. The model trained on one distribution, serves on another, and degrades silently.

Лекарство — хранилище признаков: единый источник значений признаков и для обучения, и для выдачи, гарантирующий паритет. (Правила Google #29 «обучай так, как выдаёшь», #32 «переиспользуй код между обучением и выдачей».)Fix — a feature store: one source of feature values for both training and serving, guaranteeing parity. (Google Rules #29 "train like you serve", #32 "reuse code between training and serving".)

Train/serve skew is the most common silent production failure. The root cause is two code paths computing "the same" feature slightly differently, or a feature that drifts between when you trained and when you serve. The architectural fix is the feature store — compute each feature once, write it where both training and serving read it. This is exactly the bridge node in the production blueprint two slides from now.
