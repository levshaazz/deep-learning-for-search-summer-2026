Инвертированный индексInverted index term → list of documents

Прямой индекс отображает документ → термины; ответить на запрос — значит просканировать каждый документ, \(O(N)\) по размеру корпуса.A forward index maps doc → terms; answering a query means scanning every document — \(O(N)\) in corpus size.

Инвертированный индекс переворачивает это: словарь (термин + документная частота \(\mathrm{df}\)), указывающий на список постингов (отсортированные ID документов, опционально частота термина \(\mathrm{tf}\) и позиции).An inverted index flips it: a dictionary (term + document frequency \(\mathrm{df}\)) pointing at a postings list (sorted doc IDs, optionally term frequency \(\mathrm{tf}\) and positions).

Теперь стоимость зависит от числа совпавших документов, а не от размера корпуса — вот почему поиск веб-масштаба вообще возможен.Cost now depends on the number of matching documents, not the corpus size — this is why web-scale search is even possible.

This is the one classical data structure every search person must know cold. The key insight is the cost flip: instead of \(O(N)\) over the whole corpus, you pay roughly for the length of the postings lists you intersect. Positions in the postings enable phrase queries. We will build BM25 on top of this in Lecture 03 — \(\mathrm{tf}\) and \(\mathrm{df}\) are already living in the index.
