Two worlds

A production search system = offline (index & train) + online (serve), linked by a Feature / Index Store and a feedback loop. Press →.

Offline (batch)

Query & click logs → feature & index pipeline → train the ranker → model registry. Runs on a schedule, off the request path.

Feature / Index Store

The bridge: offline writes the index and features in batch; online reads them at low latency. One source of truth kills train/serving skew.

Online (per request)

The cascade: retrieval → ranking → re-rank, narrowing ~1000 → 100 → 10; features and the index are read from the store in real time.

Model deploy

The trained ranker rolls out from the registry into serving: shadow → canary → full.

The data flywheel

Clicks and served lists are logged asynchronously → flow back into the logs → next training cycle. The system improves itself.
