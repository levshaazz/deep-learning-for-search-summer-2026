CACE

Меняешь что угодно — меняется всё. Нет чистых границ модулей: перенастроишь один признак — и поведение ниже по потоку сдвигается.Changing Anything Changes Everything. No clean module boundaries — retune one feature and downstream behaviour shifts.

Клей, конфиг и петлиGlue, config & loops

Связующий код / джунгли пайплайнов тестируются только сквозным прогоном. Долг конфигурации: один устаревший пин версии признака портит ранжирование без всяких исключений. Скрытые петли обратной связи: клики по тому, что вы отранжировали, становятся завтрашними метками.Glue code / pipeline jungles testable only end-to-end. Config debt: one stale feature-version pin degrades ranking with no exception. Hidden feedback loops: clicks on what you ranked become tomorrow's labels.

These are the debt categories from Sculley 2015, each grounded in search. CACE is why you can't reason about components in isolation. Config debt is the silent killer — a stale version pin throws no exception, the ranking just quietly rots. Hidden feedback loops connect straight back to position bias (Slide 30). The unifying theme: failure is silent, so you must monitor, which is the last framework step.
