The cascade as a table

L0 / L1 / L2 — job, cost, set size
Stage Job · model Cost / doc Set size Optimises
L0 retrieval candidate-gen · BM25 / ANN very cheap millions → \(\sim 10^{3}\) recall
L1 ranking GBDT / LTR, many features moderate \(\sim 10^{3} \to 10^{2}\) order quality
L2 re-rank cross-encoder + rules expensive \(\sim 10^{2} \to 10\) precision@k

YouTube (Covington 2016): candidate-gen millions → hundreds, ranking ~\(10^{9}\) params, serving in tens of ms. MS MARCO: a BERT cross-encoder lifted MRR 16.7 → 36.5, but only feasible on a ~100-doc shortlist.

Concrete numbers anchor the abstraction. YouTube's two-stage system (Covington et al., RecSys 2016) is the canonical example — candidate generation shrinks millions to hundreds, then a heavy ranker with ~\(10^{9}\) parameters scores the survivors, all under tens of milliseconds. MS MARCO shows the precision payoff of L2: Nogueira & Cho's BERT re-ranker more than doubled MRR, but attention is quadratic, so it is only affordable on the shortlist the cascade hands it.
