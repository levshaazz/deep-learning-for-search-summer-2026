У «é» две кодировки"é" has two encodings

NFC: U+00E9 (одна кодовая точка). NFD: e + U+0301 (комбинируемый акцент). Визуально идентичны; байтово различны → они не совпадают.NFC: U+00E9 (one code point). NFD: e + U+0301 (combining accent). Visually identical; byte-different → they fail to match.

Формы: NFC (композиция, хранение), NFD (декомпозиция), NFKC/NFKD (сворачивают похожие начертания: "ﬁ"→"fi", полноширинную "Ａ"→"A", "²"→"2"; агрессивно, с потерями).Forms: NFC (compose, storage), NFD (decompose), NFKC/NFKD (fold look-alikes: "ﬁ"→"fi", full-width "Ａ"→"A", "²"→"2"; aggressive, lossy).

Ловушка чрезмерной нормализацииThe over-normalization trap

  • ·Приведение к нижнему регистру склеивает "US" (страна) и "us" (местоимение); "Apple" и "apple".Lowercasing collapses "US" (country) and "us" (pronoun); "Apple" and "apple".
  • ·NFKC переписывает химические / математические верхние индексы (\(x^{2}\) → "x2") — уничтожает сигнал.NFKC rewrites chemistry / math superscripts (\(x^{2}\) → "x2") — destroys signal.
  • ·Современные токенизаторы LLM (GPT-2/4) почти не нормализуют (побайтово, с сохранением регистра). BERT-uncased приводит к нижнему регистру и убирает диакритику.Modern LLM tokenizers (GPT-2/4) do almost no normalization (byte-level, case-preserving). BERT-uncased lowercases + strips accents.

Закономерность: NFC + минимальное сворачивание для генерации; агрессивный NFKC + сворачивание регистра только для ключей лексического поискового индекса.Pattern: NFC + minimal folding for generation; heavy NFKC + casefold only for lexical search-index keys.

Normalization is a double-edged knife. Too little and "café" written two Unicode ways never matches; too much and you erase the very distinctions you need (U.S. vs us, code, superscripts). The right amount depends on the job: a generation model preserves nearly everything; a BM25 search index folds aggressively because recall beats precision on surface form.
