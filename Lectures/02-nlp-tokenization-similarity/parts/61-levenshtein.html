overview
Ported from Lecture 1. Levenshtein is a true metric on strings via dynamic programming, O(nm). HONDA → HYUNDAI shares H, N, D, A (but not O); a 3-edit path substitutes O→Y and inserts U and I → 3 edits. (Equivalently: turn HONDA into HYUNDA with one substitution O→Y and one insertion U, then append I.) Note you cannot do it with three pure insertions, because HONDA is not a subsequence of HYUNDAI (the O has no match). Great for spell-check and fuzzy matching, but O(nm) makes it unsuitable for long documents — there you shingle and use MinHash instead. If a student wants the grid, the bottom-right cell of the 6×8 DP table is 3.
