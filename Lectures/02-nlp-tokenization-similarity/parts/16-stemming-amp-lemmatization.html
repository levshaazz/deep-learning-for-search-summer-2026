Stemming vs. lemmatization

collapsing word forms to a root

Stemming

A crude, rule-based chopping of suffixes (e.g. the Porter stemmer). Fast and language-light — but the output is a stem, not always a real word.

i
studies → studi · caring → car

Can over-merge: universe, university both → univers.

Lemmatization

Maps a word to its dictionary lemma using a vocabulary + morphology (often with the part of speech). Slower, but the output is always a valid word.

i
studies → study · drove → drive · better → good

Needs POS: saw → see (verb) or saw (noun).

Both shrink open / opened / opens / opening to one form so a query matches every variant — the classic fix for the lexical gap. Sparse retrieval (BM25) still relies on them; neural / subword models usually skip them and let the tokenizer + embeddings handle morphology.

The two classic ways to normalize word forms (after the character-level normalization on the previous slide). Stemming is a fast heuristic that just lops off endings — cheap, but it can produce non-words and over-merge unrelated terms. Lemmatization is principled: it uses a lexicon and morphology (and ideally the POS tag) to return the true dictionary form. The payoff is the same — a search for "running" should match "ran" — which is exactly the lexical-gap problem from Lecture 1. Key modern caveat: deep models rarely stem or lemmatize; subword tokenization plus learned embeddings absorb morphology, so this lives mostly on the classical-IR/BM25 side of the course.
