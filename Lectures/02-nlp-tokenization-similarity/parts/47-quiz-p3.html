Модель насчитывает неверное число R в слове «strawberry». Лучшее единственное объяснение:A model counts the wrong number of R's in "strawberry". The best single explanation is:
AОна видит только непрозрачные куски-токены, а не отдельные буквы.It only sees opaque token chunks, never individual letters.
BСловарь слишком мал, чтобы содержать «strawberry».The vocabulary is too small to contain "strawberry".
CКонцевые пробелы испортили ввод.Trailing spaces corrupted the input.
Показать объяснениеReveal explanation
A. Атом вычисления — это токен, а не символ — «strawberry» разбивается на str+aw+berry под cl100k, поэтому модель во время выполнения никогда не осматривает буквы; чтобы посчитать R, нужны запомненные написания каждого подслова. B неверно (байтовый запасной вариант гарантирует покрытие, так что OOV «strawberry» случиться не может); C — это другой (реальный) баг.A. The atom of computation is the token, not the character — "strawberry" is split into str+aw+berry under cl100k, so the model never inspects letters at run time; counting R's requires memorised spellings for every subword. B is false (byte-level fallback guarantees coverage, so an OOV "strawberry" can't happen); C is a different (real) bug.
Reinforces slide 45. The trap is B — students invoke OOV, but byte-level fallback means "strawberry" is always representable; the issue is granularity, not coverage.
