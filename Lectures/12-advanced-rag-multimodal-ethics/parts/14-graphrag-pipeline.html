Building the graph — the offline indexing pipeline

where the edges come from, before any query arrives
Pipeline · index-time, once per corpus
extract triples → resolve & merge entities → build the graph → detect communities & pre-summarise — all offline, so query-time is just a walk.
  • 1Extract — an LLM reads each chunk and emits (head, relation, tail) triples (our llama3.1:8b ran exactly this, returning 7 triples from 3 docs).
  • 2Resolve — merge co-referent mentions (“Dana”, “Dana Reyes”, “the founder”) into one node, so edges from different documents actually connect.
  • 3Build & cluster — assemble the graph, detect communities, and pre-summarise each (the global-search step). This is the cost the boundaries slide warned about — paid once, amortised over every query.
