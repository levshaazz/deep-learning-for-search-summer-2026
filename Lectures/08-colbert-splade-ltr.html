ColBERT

эмбеддинг на токен; документы — заранее; взаимодействие на запросеan embedding per token; docs precomputed; interact at query time

Каждый токен запроса и документа получает свой 128-мерный вектор (\(E_q \in \mathbb{R}^{|q|\times128}\)). Это один общий BERT-энкодер в двух режимах: префикс \([Q]\) (с дополнением [MASK]) против \([D]\) — не две разные модели. Векторы документа считаются офлайн и кэшируются — взаимодействие происходит дёшево, на запросе (отсылка L2: всё — последовательность токенов).Each query and document token gets its own 128-dim vector (\(E_q \in \mathbb{R}^{|q|\times128}\)). It is one shared BERT encoder run in two modes: the \([Q]\) prefix (with [MASK] augmentation) vs \([D]\) — not two separate models. The document vectors are computed offline and cached — interaction happens cheaply, at query time (callback L2: everything is a sequence of tokens).

Architecture: per-token embeddings, doc precomputed, MaxSim at query time. Shapes E_q ∈ ℝ^(|q|×128).

Оператор MaxSimThe MaxSim operator

для каждого токена запроса — максимум по токенам документа, затем суммаper query token, the max over doc tokens, then the sum
$$ S_{q,d} \;=\; \sum_{i \in q} \max_{j \in d} \; E_{q_i} \cdot E_{d_j} $$

Векторы L2-нормированы, поэтому скалярное произведение — это косинус. Каждый токен запроса «салютует» одному токену документа, с которым совпадает лучше всего (\(\max_j\)); оценка — сумма этих лучших салютов. Не средний по всем парам — именно максимум, затем сумма (отсылка L2: косинус как линейка). MaxSim — это оценка релевантности, а не метрика: внутренний \(\max\) нарушает неравенство треугольника и несимметричен по запросу/документу, поэтому, в отличие от одного косинусного вектора, его нельзя проиндексировать обычным ANN в метрическом пространстве — именно поэтому PLAID (и L9) нужен особый много-векторный каскад поиска.Vectors are L2-normalized, so the dot product is a cosine. Each query token "salutes" the one document token it matches best (\(\max_j\)); the score is the sum of those best salutes. Not an average over all pairs — a max, then a sum (callback L2: cosine as a ruler). MaxSim is a relevance score, not a metric: the inner \(\max\) breaks the triangle inequality and symmetry, so unlike a single cosine vector it cannot be indexed by a generic metric-space ANN — which is precisely why PLAID (and L9) need a special multi-vector retrieval cascade.

MaxSim operator. L2-norm → dot = cosine. Max-then-sum is the key: reward matching many query tokens, each to its best partner.

Вес SPLADEThe SPLADE weight

логит → ReLU → log-насыщение; FLOPS держит разрежённостьlogit → ReLU → log-saturation; FLOPS keeps it sparse
$$ w_j \;=\; \sum_{i \in q} \log\!\big(1 + \mathrm{ReLU}(z_{ij})\big) $$

Для слова словаря \(j\): суммируем по токенам входа \(i\) значение \(\log(1+\mathrm{ReLU}(z_{ij}))\), где \(z_{ij}\) — логит MLM-головы. ReLU отбрасывает отрицательные логиты (большинство), \(\log\) усмиряет большие. Регуляризатор FLOPS штрафует плотность — поэтому вектор остаётся разрежённым и попадает в инвертированный индекс; на деле штраф применяют раздельно к запросу и документу (\(\lambda_q,\lambda_d\)): запросная разрежённость держит задержку, документная — размер индекса. The FLOPS regularizer penalizes density — so the vector stays sparse and lands in the inverted index; in practice it is applied separately to query and document (\(\lambda_q,\lambda_d\)): query sparsity bounds latency, doc sparsity bounds index size. LambdaRank

пропусти стоимость — задай градиент, взвесь на \(|\Delta\text{nDCG}|\)skip the cost — define the gradient, weight by \(|\Delta\text{nDCG}|\)
$$ \text{gradient} = 1 - \sigma(1.2) = \mathbf{0.2315} $$ $$ [\,j,i\,]: \text{nDCG} = \mathbf{0.6309} \;\longrightarrow\; [\,i,j\,]: \text{nDCG} = 1.0 $$ $$ \Delta\text{nDCG} = 1.0 - 0.6309 = \mathbf{0.3691}, \qquad \lambda = 0.2315 \cdot 0.3691 = \mathbf{0.0854} $$

LambdaRank не дифференцирует метрику — он сразу задаёт силу \(\lambda = \text{градиент} \cdot |\Delta\text{nDCG}|\). Перестановка \([j,i] \to [i,j]\) поднимает nDCG с \(\mathbf{0.6309}\) до \(1.0\) (отсылка L4), значит \(\Delta\text{nDCG} = \mathbf{0.3691}\); сила \(\lambda = \mathbf{0.0854}\) тянет \(i\) вверх, \(j\) вниз — тем сильнее, чем больше выигрыш метрики.LambdaRank doesn't differentiate the metric — it directly defines the force \(\lambda = \text{gradient} \cdot |\Delta\text{nDCG}|\). Swapping \([j,i] \to [i,j]\) lifts nDCG from \(\mathbf{0.6309}\) to \(1.0\) (callback L4), so \(\Delta\text{nDCG} = \mathbf{0.3691}\); the force \(\lambda = \mathbf{0.0854}\) pulls \(i\) up and \(j\) down — harder where the metric gain is larger.
