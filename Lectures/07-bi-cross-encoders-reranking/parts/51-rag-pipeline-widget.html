Один поток слева направо с границей офлайн / онлайн. Тяжёлая сборка индекса — один раз; на запросе — каскад (извлечение → переранжирование), затем LLM пишет ответ, обоснованный найденными отрывками, со ссылками. Качество поиска ограничивает качество ответа.One left-to-right flow with an offline / online divide. The heavy index build runs once; per query the cascade (retrieve → rerank) feeds an LLM that writes an answer grounded in the retrieved passages, with citations. Retrieval quality caps answer quality.

The whole lecture, in one stepped figure. Step zero is the offline build — ingest, chunk, embed the corpus, build the index — paid once. Step one is the online query path — embed the query, retrieve the top-k, rerank the shortlist, assemble the context — the per-request budget. Step two rings the retrieve-and-rerank pair, because that is exactly the neural cascade we built: Scouts sweep wide and cheap, Judges deliberate on the few. Step three is RAG: the language model reads the reranked context and writes an answer grounded in those passages, with citations back to the sources. And the governing law is the recall floor again — the generator can only ground in what retrieval brought back.
