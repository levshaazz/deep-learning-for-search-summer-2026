Приём РазведчикаThe Scout’s fix

одно кодирование + N дешёвых произведенийone encode + N cheap dot-products
ИдеяIdea
Кодируй порознь, считай заранееEncode apart, precompute\(O(N)\) encodes \(\to\) \(1\) encode + \(N\) dots

где N = число документов (кандидатов) в корпусе, O(N) = стоимость, которая растёт линейно по N.where N = the number of documents (candidates) in the corpus, O(N) = a cost that grows linearly with N.

Если кодировать запрос и документ порознь, вектор документа не зависит от запроса. Значит, все \(N\) векторов документов считаются офлайн, один раз. На запросе: одно кодирование запроса + \(N\) дешёвых скалярных произведений — не \(N\) прогонов модели.If we encode query and document separately, the document vector does not depend on the query. So all \(N\) document vectors are computed offline, once. At query time: one query encode + \(N\) cheap dot-products — not \(N\) model passes.

Дорогой прогон модели \(\times 10^6\) превращается в дешёвое произведение \(\times 10^6\). Это и есть Разведчик — би-энкодер.An expensive model pass \(\times 10^6\) becomes a cheap dot-product \(\times 10^6\). That is the Scout — the bi-encoder.

The fix in one line: encode separately so the document side is query-independent, then precompute it. The expensive part — running the encoder — happens once per document, offline. At query time you run the encoder once on the query and then sweep cheap dot products. That trade, a million model passes down to one model pass plus a million dot products, is the entire reason retrieval is feasible. The architecture that does it is the bi-encoder.
