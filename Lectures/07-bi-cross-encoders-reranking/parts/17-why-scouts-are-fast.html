Запрос = одно кодирование + N произведенийQuery-time = one encode + N dots\(10^6\) dots \(\ll\) \(10^6\) encodes

Векторы документов лежат в кэше, как карточки в каталоге, разложенные заранее. Найти — значит пролистать карточки (произведения), а не перечитывать каждую книгу (прогон модели). Дорого только построить каталог; пользоваться им дёшево.Document vectors sit in a cache like cards in a catalog, filed in advance. To search is to flip cards (dot-products), not re-read every book (a model pass). Only building the catalog is dear; using it is cheap.

А ещё \(N\) произведений можно сделать сублинейными приближённым поиском соседей — это L9 (ANN, джамп-гейты).And even the \(N\) dots can be made sub-linear with approximate nearest-neighbour search — that is L9 (ANN, jump-gates).

The speed case, stated once. Because the document tower is query-independent, you file every document vector in advance, like a card catalog. Searching means flipping cards — cheap dot products — instead of re-reading every book, which would be a full model pass each. Building the catalog is the expensive part, but you do it once, offline. Using it is cheap. The forward link: even the linear sweep of dot products can be made sub-linear with approximate nearest neighbour search, which is Lecture 9.
