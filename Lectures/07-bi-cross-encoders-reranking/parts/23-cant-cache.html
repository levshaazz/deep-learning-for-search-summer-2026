«Предподсчёт векторов ускорил Разведчика — предпосчитаем и оценки Судьи».“Precomputing vectors made the Scout fast — so precompute the Judge’s scores too.”

Нельзя. Вектор би-энкодера — свойство документа, одинаков для любого запроса → кэшируется. Оценка кросс-энкодера — свойство пары \((q,d)\): сменишь запрос — сменится оценка → хранить нечего.You can’t. A bi-encoder vector is a property of the document, the same for any query → it caches. A cross-encoder score is a property of the pair \((q,d)\): change the query and the score changes → there is nothing query-independent to store.

Урок.Lesson. Поэтому кросс-энкодер только переранжирует короткий список, но не извлекает (ties to S08).So a cross-encoder only reranks a shortlist; it cannot retrieve (ties to S08).

Close the loop on caching. The reason precompute worked for the Scout is that a bi-encoder vector belongs to the document alone — it is identical for every query, so you store it once. A cross-encoder score belongs to the pair: change the query and the score changes, so there is nothing query-independent to precompute. That is the deep reason you cannot retrieve with a cross-encoder, only rerank a shortlist that a Scout already retrieved. It ties straight back to the O of N wall from slide eight.
