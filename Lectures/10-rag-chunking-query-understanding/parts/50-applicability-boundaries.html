«Всегда добавляй больше техник поиска — если переранжирование, CRAG и self-RAG каждый добавляют качество, то сложить их все наверняка лучше всего».“Always add more retrieval techniques — if re-rank, CRAG and self-RAG each add quality, stacking all of them must be best.”

Каждая стадия добавляет вызов LLM, задержку и новую точку отказа — оценщик может ошибиться в оценке, реранкер может снова закопать. Цена накапливается; качество насыщается. Многие техники бьют по одному и тому же отказу: если проблема в формулировке, multi-query её уже чинит — добавление CRAG не даёт ничего, кроме задержки. Сначала диагностируй режим отказа, затем добавь одну стадию, чей прирост ему подходит. Начни с наивного; заслужи каждую стадию измеренным выигрышем — это ровно то, что автоматизирует adaptive-RAG.Every stage adds an LLM call, latency, and a new failure point — a grader can mis-grade, a re-ranker can re-bury. Cost compounds; quality saturates. Many techniques target the same failure: if your problem is phrasing, multi-query already fixes it — adding CRAG buys nothing but latency. Diagnose the failure mode first, then add the one stage whose lift matches it. Start naive; earn each stage with a measured win — which is exactly what adaptive-RAG automates.
