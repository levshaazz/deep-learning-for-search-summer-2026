Логическая маршрутизацияLogical routing

пусть LLM выбирает источник данныхlet the LLM pick the data source
ОпределениеDefinition
Дай LLM меню источников данных (индексы, инструменты) и пусть она классифицирует, к какому относится запрос — вызов функции над ограниченным набором.Give the LLM a menu of data sources (indices, tools) and have it classify which one the query belongs to — a function call over a constrained set.
  • ·Пример: вопрос по коду направляется в документацию; про биллинг — в SQL-базу; общий — в веб. Один классификатор, несколько бэкендов.Example: a code question routes to docs; billing to the SQL database; general to the web. One classifier, several back-ends.
  • ·Как: структурированный вывод (enum / схема вызова функции), чтобы маршрут был валидной меткой, по которой система диспетчеризует — а не свободным текстом.How: structured output (an enum / function-calling schema), so the route is a valid label the system dispatches on — not free text.
  • ·против семантической: логическая рассуждает над явным меню; семантическая (далее) выбирает по сходству эмбеддингов — логическая, когда варианты именуемы.vs semantic: logical reasons over an explicit menu; semantic (next) picks by embedding similarity — logical when choices are nameable.
logical-routing definition. LLM classifies the query into one of a named menu of sources/indices/tools (structured output / function call). Contrast with semantic routing (similarity-based). No gated numbers.
