Four ways to cut

fixed · recursive · semantic · late — cost vs structure (representative)
strategy how it cuts cost when to use
fixed-sizeevery N tokens, hard boundaries (optionally with overlap)cheapestuniform text, fast baseline; pair with overlap to soften boundaries
recursivesplit on a separator hierarchy (¶ → sentence → word) until each piece fits Ncheapstructured prose / markdown / code where natural boundaries matter
semanticembed sentences, start a new chunk where adjacent-sentence similarity dropsmoderate (one embed pass)topic-shifting docs where fixed cuts split ideas
late-chunkingembed ALL tokens of the long doc first, chunk AFTER the transformer (before pooling)needs a long-context encoder; training-freewhen chunk embeddings must keep full-document context

Going down the table trades cheapness for structure-awareness. The first three cut before embedding, so each chunk is embedded in isolation; late-chunking inverts the order — embed first, cut later — which is the frontier idea on the next slide.
