Индексация нескольких представленийMulti-representation indexing

индексируй сводку, извлекай полный чанкindex a summary, retrieve the full chunk
ОпределениеDefinition
Эмбеддим и индексируем производное представление каждого документа — сводку, гипотетический вопрос, набор пропозиций — но генератору возвращаем полный чанк.Embed and index a derived representation of each document — a summary, a hypothetical question, a set of propositions — but return the full chunk to the generator.
  • ·Зачем: то, что лучше читается для поиска (краткая сводка под запрос), — это не то, что лучше для генерации (полный пассаж с деталями). Так разделим их: индексируем сводку, храним указатель на сырой чанк.Why: what reads best for retrieval (a tight summary that matches a query) is not what reads best for generation (the full passage with the details). So split them: index the summary, store a pointer to the raw chunk.
  • ·Примеры: индексация по сводке, поиск «родительского документа» (совпал маленький чанк — вернём его больший родитель) и индексация по гипотетическому вопросу.Examples: summary-indexing, "parent-document" retrieval (match a small chunk, return its larger parent), and hypothetical-question indexing.
  • ·Отсылка (L8): ColBERT — родственная, но отдельная идея — мульти-векторный индекс: много векторов одного текста, а не (как здесь) индексация производного вида с возвратом оригинала. (Мы разобрали его в L8; здесь это один из нескольких приёмов.)Callback (L8): ColBERT is a related but distinct idea — a multi-vector index: many vectors of the same text, not (as here) indexing a derived view and returning the original. (We taught it in L8; here it's one of several.)
