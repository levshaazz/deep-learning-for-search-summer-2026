Индексация нескольких представленийMulti-representation indexing

индексируй сводку, извлекай полный чанкindex a summary, retrieve the full chunk
ОпределениеDefinition
Эмбеддим и индексируем производное представление каждого документа — сводку, гипотетический вопрос, набор пропозиций — но генератору возвращаем полный чанк.Embed and index a derived representation of each document — a summary, a hypothetical question, a set of propositions — but return the full chunk to the generator.
  • ·Зачем: что лучше для поиска (краткая сводка под запрос) — не то, что лучше для генерации (полный пассаж с деталями). Разделим их: индексируем сводку, храним указатель на сырой чанк.Why: what's best for retrieval (a tight summary matching the query) isn't what's best for generation (the full passage with details). So split them: index the summary, point to the raw chunk.
  • ·Примеры: индексация по сводке, поиск «родительского документа» (совпал маленький чанк — вернём родителя) и индексация по гипотетическому вопросу.Examples: summary-indexing, "parent-document" retrieval (match a small chunk, return its parent), and hypothetical-question indexing.
  • ·Отсылка (L8): ColBERT — родственная, но отдельная идея: мульти-векторный индекс — много векторов одного текста, а не (как здесь) индексация производного вида с возвратом оригинала.Callback (L8): ColBERT is a related but distinct idea: a multi-vector index — many vectors of the same text, not (as here) indexing a derived view and returning the original.
multi-representation-indexing definition. Index a derived view (summary / hypothetical question / proposition / parent-doc), return the full chunk. ColBERT is a ONE-LINE callback only (L8 owns it — do not re-teach MaxSim).
