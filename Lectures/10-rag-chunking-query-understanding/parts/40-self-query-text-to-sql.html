Self-query & text-to-SQL, by example

the LLM compiles intent into a query

self-query · NL → metadata filter

// "papers on retrieval published after 2020"
{
  "topic": "retrieval",
  "year": { "$gt": 2020 }
}
// applied ALONGSIDE the vector search:
// filter first, then rank within the matches

text-to-SQL · NL → SQL

-- "how many documents did we
--  index last month?"
SELECT COUNT(*)
FROM documents
WHERE indexed_at >= date_trunc(
  'month', now() - interval '1 month'
);

Self-query keeps the vector search but adds an exact filter; text-to-SQL leaves the vector world entirely for an executable query over a structured store. Both turn a fuzzy question into something the back-end can run precisely.

self-query & text-to-SQL walkthrough (l10-routing.construct). Two construction examples — metadata filter (self-query, applied alongside vector search) and executable SQL (text-to-SQL). The 2020 in the filter is a year, not a 2dp decimal; SQL has no gated numbers.
