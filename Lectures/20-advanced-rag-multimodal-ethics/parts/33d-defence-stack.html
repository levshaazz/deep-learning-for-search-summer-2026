Границы применимости. Ни один слой не абсолютен — это защита в глубину: считай найденный контент недоверенным, а ассистента — уязвимым, и клади слои так, чтобы пробой одного не давал ни исполнения, ни эксфильтрации. Общего решения prompt injection пока нет.Boundaries. No layer is absolute — this is defence in depth: treat retrieved content as untrusted and the assistant as fallible, and stack layers so one breach yields neither execution nor exfiltration. There is no general solution to prompt injection yet.

The defence stack — the centerpiece of the security turn, deliberately paired with each layer's limit so students learn defence in depth, not a silver bullet. Five layers map to the three risks: instruction isolation + input sanitization blunt injection; the rendering allow-list + CSP close the exfiltration channel; least-privilege tools cap the blast radius; corpus write control raises the poisoning cost. Every row carries a boundary because each defence is evadable alone — markers spoofable, keyword filters paraphrasable, read-only leaks survive tool scoping. The honest frame: no general solution to prompt injection exists (OWASP LLM Top-10, Simon Willison's ongoing writeups) — assume the assistant is fallible and layer accordingly.
