Практически важнее всего вторая колонка. Позднее чанкование меняет только вектор — в промпт генератора уходит тот же исходный текст чанка. Contextual Retrieval меняет сам чанк: он раздувается примерно на сотню токенов, и у моделей с жёстким лимитом входа хвост чанка может молча обрезаться (прямое предупреждение из cookbook). The second column is the one that matters in practice. Late chunking changes only the vector — the generator receives the same original chunk text. Contextual Retrieval changes the chunk itself: it grows by roughly a hundred tokens, and on models with a hard input limit the tail can be silently truncated (a warning straight from the cookbook).

И совет из того же источника, который ты не услышишь от продавца векторной базы: если весь корпус меньше двухсот тысяч токенов — не строй индекс, положи его в промпт целиком. And the advice from that same source that no vector-database vendor will give you: if your whole corpus is under two hundred thousand tokens, do not build an index — put it in the prompt.

The organising axis of the act: WHEN is the missing context restored. Before the embedding — Contextual Retrieval rewrites the TEXT with an LLM (about $1.02 per million document tokens with prompt caching, claude-3-haiku-20240307). During — late chunking changes only the VECTOR, so the generator still receives the original passage. After — late interaction defers the comparison and pays MaxSim per query. The practical consequence students miss: because Contextual Retrieval physically grows each chunk by ~100 tokens, a model with a hard input limit silently truncates it — Anthropic's own cookbook says so. And the honest closing note from the same source: under ~200k tokens of corpus, skip retrieval and put the whole thing in the prompt.
