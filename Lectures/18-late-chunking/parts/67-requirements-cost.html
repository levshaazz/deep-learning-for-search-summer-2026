Счёт за приём The cost ledger

На индексации — дороже: внимание по документу растёт как \(O(n^2)\) по длине окна, и нужно держать в памяти токен-эмбеддинги всего документа до усреднения.Index-time — higher: attention over the document grows as \(O(n^2)\) in the window length, and you must hold the document’s token embeddings in memory until the pooling.

На запросе — бесплатно: хранится по-прежнему один вектор на чанк, стоимость поиска идентична наивной.Query-time — free: you still store one vector per chunk, so search cost is identical to naive.

В §3.1 статьи написано, что память растёт «экспоненциально». Это оговорка: память внимания квадратична по длине окна. Цитируй с поправкой.§3.1 of the paper says memory grows “exponentially”. That is a slip: attention memory is quadratic in the window length. Quote it with the correction.

Requirements, now with PROVENANCE — the old version attributed all of them to the paper, which is wrong. The paper says only: any long-context text embedding model that uses MEAN POOLING, with token-level outputs. "CLS or max pooling are incompatible" appears only in Jina's blog Part II, never in the paper. And last-token pooling (e5-mistral, gte-Qwen, NV-Embed) is not discussed ANYWHERE — say that plainly; it is a real hole and a good exam question. Cost: index-time attention is O(n²) in the window and you must hold whole-document token embeddings until pooling; query time is unchanged. Note the paper's §3.1 says "exponentially" where it means quadratically.
