Оператор MaxSimThe MaxSim operator

для каждого токена запроса — максимум по токенам документа, затем суммаper query token, the max over doc tokens, then the sum
$$ S_{q,d} \;=\; \sum_{i \in q} \max_{j \in d} \; E_{q_i} \cdot E_{d_j} $$

где Sq,d = оценка релевантности пары запрос–документ, i = токен запроса, j = токен документа, Eqi = эмбеддинг токена запроса, Edj = эмбеддинг токена документа (оба L2-нормированы, поэтому скалярное произведение — это косинус).where Sq,d = the query–document relevance score, i = a query token, j = a document token, Eqi = the query token's embedding, Edj = the document token's embedding (both L2-normalized, so the dot is a cosine).

Векторы L2-нормированы, поэтому скалярное произведение — это косинус. Каждый токен запроса «салютует» одному токену документа, с которым совпадает лучше всего (\(\max_j\)); оценка — сумма этих лучших салютов. Не средний по всем парам — именно максимум, затем сумма (отсылка L2: косинус как линейка). MaxSim — это оценка релевантности, а не метрика: внутренний \(\max\) нарушает неравенство треугольника и несимметричен по запросу/документу, поэтому, в отличие от одного косинусного вектора, его нельзя проиндексировать обычным ANN в метрическом пространстве — именно поэтому PLAID (и L9) нужен особый многовекторный каскад поиска.Vectors are L2-normalized, so the dot product is a cosine. Each query token "salutes" the one document token it matches best (\(\max_j\)); the score is the sum of those best salutes. Not an average over all pairs — a max, then a sum (callback L2: cosine as a ruler). MaxSim is a relevance score, not a metric: the inner \(\max\) breaks the triangle inequality and symmetry, so unlike a single cosine vector it cannot be indexed by a generic metric-space ANN — which is precisely why PLAID (and L9) need a special multi-vector retrieval cascade.

MaxSim operator. L2-norm → dot = cosine. Max-then-sum is the key: reward matching many query tokens, each to its best partner.
