## The promise, and the one thing that could break it

L7 teaches the circuit grammar in four slides and then uses it. **L9 is where the notation earns its
keep**: it shows that the diagram is not a picture *of* the computation, it *is* the computation —
isomorphic to the einsum string, and therefore to the cost.

The promise is: **you can read the bill off the picture.** So the lecture may not PRINT a cost table.
Every number it shows is derived, at the board, from one rule:

> an `(a×b)·(b×c)` matmul costs `2·a·b·c` flops — one multiply and one add per triple.

Apply it to the glyphs of one block and the whole lecture falls out:

| glyph | shape | flops |
|---|---|---|
| `Wq, Wk, Wv` chipped rectangles | 3 × (n×d)·(d×d) | `6nd²` |
| `L_O` | (n×d)·(d×d) | `2nd²` |
| FFN (two rectangles) | (n×d)·(d×4d), (n×4d)·(4d×d) | `16nd²` |
| **the cup** `QKᵀ` | (n×d)·(d×n) | `2n²d` |
| **the second cup** `A·V` | (n×n)·(n×d) | `2n²d` |

`linear = 24nd²` · `attention core = 4n²d` · **crossover: `4n²d = 24nd²` ⟺ `n = 6d`.**

For BERT-base (d=768) that is **4608 tokens**. Attention is **10.0%** of a block at n=512, **47.1%** at
4096, **87.7%** at 32768. *That* is the lecture: everyone knows attention is quadratic; almost nobody
can say where the quadratic term starts to matter — because the formula does not show it and the
diagram does.

Memory bites long before flops do: the n×n box is `h·n²·2` bytes → **6.3 MB → 403 MB → 25.8 GB**
(the numbers L7 and L8 already print; `gen_l19.py` asserts against them, so the lecture that DERIVES
the bill cannot contradict the two that print it).

## Acts (target ≈ 57 slides; the L15–L20 bar is the floor, not the ceiling)

**Front (01–05)** title · you-are-here · agenda · objectives · hook *(a week lost to a bug that never

**II — The grammar (13–22).** divider · wire = axis `ncd-embedding` · chipped rectangle = a learned

(it normalises, it does not eat) · hexagon = reindex / slice / mask / top-k / concat · dashed region =
broadcast `ncd-posenc` · ⊕ and ◎ · the vocabulary on one card · quiz.

**III — Reading (23–30).** divider · attention glyph by glyph `ncd-attention` · **the worked chain**
`ncd-chain` (the cat sat → a rank) · heads SPLIT the width `ncd-multihead` · the mask is a hexagon
`ncd-causal` · the block `ncd-block` · the encoder as one figure `ncd-atlas`.

**IV — The bill (31–40) — the payoff.** divider · hook: *at what n does O(n²) start to matter?* · the
counting rule · count the glyphs of one block · the table (10% → 47% → 88%) · the crossover n = 6d ·
misconception: at training lengths the expensive part is the FFN nobody draws · memory bites first
(6.3 MB → 25.8 GB) · FlashAttention never materialises the box (**the wire stays, the tensor goes**) ·
the KV cache is the axis that GROWS `ncd-kvcache` (36.9 KB/token; MQA 12× smaller — and the diagram
shows why: MQA never touches the query wire).

**V — Debugging (41–46).** divider · the three broken circuits `ncd-debug` · the shape-preserving bug in
detail · how it actually shows up (loss plateaus, attention entropy — no stack trace, ever) · what a
shape checker can and cannot catch · exercise.

**VI — Writing your own (47–52).** divider · circuit → einsum → code · bi-encoder vs cross-encoder
`ncd-retrieval` · ANN `ncd-ann` · RAG `ncd-rag` · frontier: the diagram as an *optimisation* tool
(FlashAttention on a napkin).

**VII — Boundaries & close (53–57).** what the notation cannot say (control flow, data-dependent
shapes, training dynamics, numerics) · when NOT to draw · synthesis · references · final.
